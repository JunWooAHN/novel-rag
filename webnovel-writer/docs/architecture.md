# 시스템 아키텍처와 모듈 설계

## 핵심 이념

### 환각 방지 3법칙

| 법칙 | 설명 | 실행 방식 |
|------|------|---------|
| **개요가 곧 법률** | 개요를 준수하며, 임의로 변경하지 않음 | Context Agent 가 챕터 개요를 강제 로드 |
| **설정이 곧 물리법칙** | 설정을 준수하며, 자기모순을 허용하지 않음 | Consistency Checker 가 실시간 검증 |
| **새로운 요소는 식별 필수** | 새로운 엔티티는 반드시 데이터베이스에 등록 관리 | Data Agent 가 자동 추출 및 중복 해소 |

### Strand Weave 리듬 시스템

| Strand | 의미 | 이상적 비율 | 설명 |
|--------|------|---------|------|
| **Quest** | 메인 스토리라인 | 60% | 핵심 갈등 추진 |
| **Fire** | 감정선 | 20% | 인물 관계 발전 |
| **Constellation** | 세계관 확장 | 20% | 배경/세력/설정 |

리듬 레드라인：

- Quest 연속 5챕터 초과 금지
- Fire 공백 10챕터 초과 금지
- Constellation 공백 15챕터 초과 금지

## 듀얼 Agent 아키텍처

### Context Agent（읽기）

역할：집필 전 “창작 태스크 브리프”를 구성하여 해당 챕터의 컨텍스트, 제약 조건 및 독자 몰입 전략을 제공합니다.

### Data Agent（쓰기）

역할：본문에서 엔티티와 상태 변화를 추출하고, `state.json`, `index.db`, `vectors.db`를 업데이트하여 데이터 체인의 폐쇄 루프를 보장합니다.

## 6차원 병렬 심사

| Checker | 검사 중점 |
|---------|---------|
| High-point Checker | 쾌감 포인트 밀도와 품질 |
| Consistency Checker | 설정 일관성（전투력/장소/타임라인） |
| Pacing Checker | Strand 비율과 공백 |
| OOC Checker | 인물 행동이 캐릭터 설정에서 벗어나는지 여부 |
| Continuity Checker | 장면과 서사 연속성 |
| Reader-pull Checker | 훅 강도, 기대 관리, 독자 몰입력 |

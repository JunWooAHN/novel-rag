# 단서 설계와 공정성 (Clue Design & Fair Play)

> **핵심 원칙**: 단서는 추리의 기초다. 공정한 단서 설계 = 독자가 볼 수 있음 + 독자가 이해할 수 있음 + 독자가 추리할 수 있음.

---

## 1. "공정한 단서"란?

### 정의
**공정한 단서(Fair Clue)**: 탐정이 발견한 모든 핵심 단서는 반드시 동시에 독자에게 보여줘야 하며, 독자가 **이론적으로** 이 단서들을 기반으로 진실을 추리할 수 있어야 한다.

### 3대 기준
```markdown
✅ 기준1: 가시성(Visibility)
단서는 반드시 글에서 명확히 제시되어야, 탐정 머릿속에만 존재하면 안 됨

✅ 기준2: 이해 가능성(Comprehensibility)
단서의 의미는 독자가 이해할 수 있어야, 전문 지식에 의존하면 안 됨

✅ 기준3: 추론 가능성(Deducibility)
단서를 기반으로, 독자가 진실에 도달할 수 있어야 (또는 근접)
```

---

## 2. 단서의 분류

### 기능별 분류

#### 유형1: 지시 단서(Pointing Clue)
**역할**: 직접 범인이나 진실을 가리킴

**예시**:
```markdown
단서: 범인이 현장에 이름이 새겨진 반지를 남김
→ 직접 범인 신원을 가리킴
```

---

#### 유형2: 배제 단서(Elimination Clue)
**역할**: 어떤 가능성을 배제, 범위를 좁힘

**예시**:
```markdown
단서: 사건 발생 시 새벽 3시, 장삼에게는 알리바이가 있음
→ 장삼이 범인일 가능성을 배제
```

---

#### 유형3: 연결 단서(Connecting Clue)
**역할**: 무관해 보이는 두 사건이나 인물을 연결

**예시**:
```markdown
단서A: 피해자가 생전에 익명의 협박장을 받음
단서B: 이사의 타자기에서 한 글자 키가 빠져 있음
→ 추측: 협박장은 이사가 쓴 것일 수 있음
```

---

#### 유형4: 시간 단서(Temporal Clue)
**역할**: 사건 발생의 시간 순서를 확정

**예시**:
```markdown
단서: 피해자의 시계가 저녁 8시에 멈춤
→ 추측: 사건 발생 시간은 저녁 8시일 수 있음
```

---

#### 유형5: 반전 단서(Reversal Clue)
**역할**: 이전의 추리를 뒤집어, 반전을 유발

**예시**:
```markdown
이전 단서: 흉기는 단도
반전 단서: 법의학이 치명상이 사실 둔기로 인한 것임을 발견
→ 단도가 흉기라는 가설을 뒤집음
```

---

### 중요도별 분류

| 등급 | 명칭 | 역할 | 비율 |
|------|------|------|------|
| **A급** | 핵심 단서 | 직접 진실을 가리킴 | 10% |
| **B급** | 핵심 단서 | 용의자 범위를 좁힘 | 30% |
| **C급** | 보조 단서 | 배경 정보 제공 | 40% |
| **D급** | 장식 단서 | 분위기 조성 | 20% |

**주의**: A급 단서는 중요하지만, 수가 너무 많으면 너무 쉽게 맞춰짐.

---

## 3. 단서 매설 기법

### 기법1: 사전 매설(Foreshadowing)
**정의**: 사건 발생 전이나 탐정 조사 전에, "무심코" 핵심 물품이나 정보를 언급.

**예시**:
```markdown
## 사례: 독살 사건
3화(사건 전):
"장삼이 정원에서 협죽도를 꺾어, 방 장식용이라고 했다."

15화(사건 후):
법의학: "피해자는 협죽도 중독으로 사망했습니다."
→ 독자가 깨달음: 3화의 협죽도가 핵심이었어!
```

**포인트**: 사전 매설은 **자연스러워야** 하며, 너무 의도적이면 안 됨.

---

### 기법2: 배경으로 위장(Camouflage)
**정의**: 핵심 단서를 환경 묘사나 일상 대화 속에 숨김.

**예시**:
```markdown
## 사례: 밀실 살인
7화(환경 묘사):
"방 구석의 벽장 문이 살짝 열려 있었고, 문틀에 약간의 긁힌 자국이 있었다."

20화(밝혀짐):
탐정: "범인이 벽장 안에 숨어 있었고, 긁힌 자국은 그가 드나들 때 남긴 것이다."
```

**포인트**: 독자가 처음 읽을 때는 무시할 수 있지만, 다시 읽으면 발견할 수 있어야.

---

### 기법3: 여러 번 언급(Repetition)
**정의**: 중요 단서가 글에서 2-3번 등장하여, 독자 인상을 깊게 함.

**예시**:
```markdown
5화: 피해자 손에 비싼 시계가 있음
12화: 탐정이 피해자 시계의 바늘이 8시에 멈춘 것을 발견
18화: 탐정: "이 시계가 핵심이야..."
```

**포인트**: 매번 언급할 때 각도가 다르며, 점진적으로 중요성을 밝힘.

---

### 기법4: 대비 제시(Contrast)
**정의**: 대비를 통해, 독자가 이상한 점을 알아차리게 함.

**예시**:
```markdown
장삼의 증언: "나는 8시에 집에 돌아갔어."
CCTV 기록: 장삼이 8시 15분에야 회사를 떠남.
→ 독자 발견: 장삼이 거짓말하고 있다
```

---

### 기법5: 분산 제시(Scattered Clues)
**정의**: 완전한 단서를 여러 조각으로 나누어, 다른 챕터에 분산.

**예시**:
```markdown
10화: 피해자 일기에 "7월 15일에 그를 만남"이라 적혀 있음
15화: 이사의 일정표에 7월 15일 A시에 간 것으로 표시
20화: A시는 피해자의 고향
→ 추측: 이사가 A시에서 피해자를 만남
```

**포인트**: 조각 하나만으로는 눈에 띄지 않지만, 조합하면 의미가 있음.

---

## 4. 단서 제시의 "3층법"

### 층위1: 명시 단서(Obvious Clue)
**정의**: 독자에게 "이것이 단서다"라고 명확히 알려줌

**예시**:
```markdown
탐정이 머리카락 하나를 집어 들었다: "이것이 핵심 단서야."
```

**역할**: 독자 주의를 유도, 입문자용 작품에 적합

---

### 층위2: 암시 단서(Subtle Clue)
**정의**: 명확히 말하지 않지만, 경험 있는 독자는 알아볼 수 있음

**예시**:
```markdown
탐정이 방을 둘러보다가, 시선이 벽장 문에 잠시 멈췄다.
```

**역할**: 독자에게 추리 공간 부여, 참여감 증가

---

### 층위3: 숨겨진 단서(Hidden Clue)
**정의**: 극도로 은밀하여, 다시 읽을 때만 발견 가능

**예시**:
```markdown
5화(잡담):
이사: "요즘 불면증이 심해서, 수면제에 의존하고 있어."

30화(밝혀짐):
탐정: "범인이 수면제로 피해자를 기절시켰어... 이사가 수면제가 있다고 했었잖아!"
```

**역할**: "그때 그랬구나!"하는 놀라움 조성

---

### 3층 배합 추천
```markdown
명시 단서: 40% (독자가 따라올 수 있도록)
암시 단서: 40% (추리 공간 부여)
숨겨진 단서: 20% (놀라움 조성)
```

---

## 5. 공정성 검증 리스트

### 점검1: 단서가 독자에게 제시되었는가?
**잘못**:
```markdown
탐정(생각): 나는 현장에서 핵심 증거를 발견했다.
→ 독자는 어떤 증거인지 모름
```

**올바름**:
```markdown
탐정이 탁자 아래에서 찢어진 메모를 발견했다.
→ 독자가 동시에 증거를 봄
```

---

### 점검2: 단서가 이해 가능한가?
**잘못**:
```markdown
탐정: "이 반점은 청산가리 중독의 전형적 증상입니다."
→ 독자는 화학 지식이 없어 추리 불가
```

**올바름**:
```markdown
탐정: "이 반점은 중독 증상입니다. 그리고 현장에서 화학 배경을 가진 사람은 이사뿐입니다."
→ 전문 지식을 단순화, 독자가 이해 가능
```

---

### 점검3: 단서가 충분한가?
**기준**:
```markdown
✅ 핵심 진실에 최소 **3개의 독립 단서** 필요
✅ 각 단서 하나만으로는 눈에 띄지 않지만, 조합하면 진실을 가리킴
```

---

### 점검4: "작가 전지적 함정"이 없는가?
**정의**: 작가가 진실을 알기에, 독자도 "알아야 한다"고 기본 전제함.

**피하는 방법**:
```markdown
✅ 중요 단서는 최소 **2번** 언급
✅ 테스트 독자에게 읽게 하여, 진실을 추리할 수 있는지 확인
```

---

## 6. 단서와 레드 헤링의 균형

### 황금 비율
```markdown
진짜 단서(진실을 가리킴): 60%
레드 헤링(오도): 40%
```

**역할**: 독자에게 추리 단서를 주면서도, 진실이 너무 쉽게 맞춰지지 않게.

---

### 레드 헤링 사용 원칙
**원칙1**: 레드 헤링은 반드시 **사후 설명 가능**해야

**잘못**:
```markdown
10화: 장삼이 현장에, 손에 피가 묻음
30화: 탐정: "그건 중요하지 않아, 진범은 이사야."
→ 장삼의 핏자국 설명 없음, 독자가 불합리하다고 느낌
```

**올바름**:
```markdown
10화: 장삼이 현장에, 손에 피가 묻음
30화: 탐정: "장삼의 피는 피해자 상처를 처치해주면서 묻은 것이다."
→ 합리적 설명
```

---

**원칙2**: 레드 헤링은 완전히 허구로 만들면 안 됨

**잘못**:
```markdown
작가가 갑자기 조작: "이사에게 사실 쌍둥이 형제가 있었다."
→ 앞에서 전혀 언급 없음, 독자가 추리 불가
```

**올바름**:
```markdown
5화: 이사의 어머니가: "어릴 때 넌 동생이랑 항상 싸웠지."
30화: 이사에게 동생이 있었고, 진범임이 밝혀짐
→ 앞에 복선 있음
```

---

## 7. 단서 밀도 조절

### 밀도 추천
```markdown
매 화 단서 수: 1-3개
매 10화마다 최소: 1개 핵심 단서(A급)
```

**너무 적음**: 독자가 추리 불가
**너무 많음**: 독자 정보 과부하

---

### 단서 분포 전략

#### 전반 (1-30% 진행)
```markdown
- 기초 단서 매설
- 인물 관계 구축
- 의심 포인트 암시
```

#### 중반 (30-70% 진행)
```markdown
- 점진적으로 핵심 단서 밝힘
- 레드 헤링으로 오도
- 작은 반전 만들기
```

#### 후반 (70-100% 진행)
```markdown
- 모든 단서 종합
- 핵심 진실 밝힘
- 레드 헤링 설명
```

## 8. 단서 설계 사례 분석

### 사례1: 《오리엔트 특급 살인》

**단서 제시**:
```markdown
단서1: 12명의 용의자 모두 완벽한 알리바이
단서2: 피해자에게 12곳의 칼에 찔린 상처
단서3: 각 용의자와 피해자 모두 간접적 연결
```

**공정성**:
- ✅ 모든 단서 공개 제시
- ✅ 독자가 추리 가능: 12명 공동 범행
- ✅ 진실이 의외이면서도 합리적

---

### 사례2: 《그리고 아무도 없었다》

**단서 제시**:
```markdown
단서1: 동요가 살인 순서를 암시
단서2: 각 피해자의 사인이 동요에 대응
단서3: 판사가 "살해"된 후 의사가 사망을 확인
```

**공정성**:
- ✅ 동요가 미리 제시
- ✅ 독자가 사망 순서를 추측 가능
- ✅ 하지만 판사의 가짜 죽음 트릭은 예측하기 어려움 (의외성)

---

## 9. 흔한 단서 설계 오류

### 오류1: 단서가 너무 명확
**예시**:
```markdown
5화: 이사가: "난 그를 죽도록 미워해, 정말 죽이고 싶어!"
→ 너무 명확, 독자가 즉시 이사를 의심
```

**개선**:
```markdown
5화: 이사(낮은 소리로): "언젠가..."
→ 암시하되 명확히 말하지 않음
```

---

### 오류2: 단서가 너무 숨겨짐
**예시**:
```markdown
3화: 탁자 위에 파리가 한 마리
30화: 탐정: "파리가 방 창문이 열린 적 있다는 것을 증명해!"
→ 독자가 파리를 전혀 주목 안 함
```

**개선**:
```markdown
3화: 탐정이 눈살을 찌푸렸다: "이상해, 이 계절에 어떻게 파리가 있지?"
→ 독자의 주의를 끎
```

---

### 오류3: 단서가 자기 모순
**예시**:
```markdown
10화: 피해자 시계가 8시에 멈춤
15화: 목격자가 8시 30분에 총성을 들었다고 함
→ 시간선 모순
```

**해결**:
```markdown
20화: 탐정: "시계는 범인이 일부러 늦춘 것이다!"
→ 모순 설명
```

---

## 10. 단서 설계 도구

### 도구1: 단서 등록표
```markdown
| 단서ID | 등장 챕터 | 내용 | 유형 | 중요도 | 가리키는 대상 |
|--------|---------|------|------|--------|------|
| C01 | 5화 | 핏자국 손수건 | 물증 | A급 | 이사 |
| C02 | 10화 | 알리바이 | 증언 | B급 | 장삼 배제 |
```

---

### 도구2: 공정성 점검 리스트
```markdown
- [ ] 모든 A급 단서가 독자에게 제시되었는가?
- [ ] 단서가 이해 가능한가 (전문 지식 불필요)?
- [ ] 최소 3개의 독립 단서가 진실을 가리키는가?
- [ ] 레드 헤링이 사후 설명 가능한가?
- [ ] 단서 밀도가 합리적인가 (매 화 1-3개)?
```

---

### 도구3: 테스트 독자 검증법
**절차**:
```markdown
1. 3-5명의 테스트 독자 선정
2. 진실 밝히기 전 한 화까지 읽게 함
3. 추리 결과 질문
4. 아무도 추리 못 함 → 단서 부족
   모두 맞춤 → 단서 너무 명확
   소수가 맞춤 → 공정성 양호
```

## 단서 설계 빠른 참조표

|---------|------|---------|---------|

| **연결 단서** | 사건 연결 | 2-3개 | 암시 |
| **반전 단서** | 반전 만들기 | 1-2개 | 숨겨진 |

## 부록: 단서 설계 황금 법칙

1. **3-2-1 법칙**: 핵심 진실에 최소 **3개의 독립 단서** 필요, 그 중 **2개 명확**, **1개 은밀**
2. **이중 제시**: 중요 단서는 반드시 **최소 2번 등장**
3. **합리적 설명**: 모든 레드 헤링은 반드시 **사후 설명 가능**
4. **테스트 검증**: 완성 후 테스트 독자로 공정성 검증

## 총결

**공정한 단서 설계 = 가시성 + 이해 가능성 + 추론 가능성**

기억하자: 단서는 "과시"하기 위한 것이 아니라, 독자에게 진실을 추리할 **능력**을 주기 위한 것이다. 공정한 경쟁의 재미는 "나도 생각해낼 수 있었어"에 있다.

## 3대 법칙 (낮은 자유도 - 반드시 정확히 실행)

| 법칙 | 규칙 | 확인 방법 |
|------|------|----------|
| **대강이 곧 법률** | 대강을 엄격히 실행하며, 임의 발휘 금지 | 검토 시 대강과 대조 |
| **설정이 곧 물리법칙** | 실력/기술/아이템 ≤ index.db 기록 | 작성 전 쿼리 확인 |
| **발명에는 식별 필요** | 새 엔티티는 Data Agent가 자동 추출 | 챕터 완성 후 처리 |

## 새 엔티티 처리 프로세스

현재 규칙: 본문에 XML 태그 불필요:

1. **작성 시**: 순수 본문을 직접 작성, 새 캐릭터/장소/아이템은 정상적으로 묘사
2. **완성 후**: Data Agent가 새 엔티티를 자동 식별하여 index.db에 기록
3. **불확실한 엔티티**: Data Agent가 uncertain으로 표시, 수동 확인

## 챕터 제약 계층

### Hard (필수)

- 본 챕터 가독성 기준 충족: 독자가 "무슨 일이 일어났는지 / 누가 무엇을 하는지 / 왜"에 답할 수 있어야 함.
- 본 챕터에 명확한 추진이 존재해야 함: 문제, 목표, 대가, 관계 변화, 정보 변화 중 최소 하나가 식별 가능해야 함.
- 이전 챕터에 명확한 약속(훅/미해결 문제)이 있었다면, 본 챕터에서 반드시 응답(부분 실현 허용, 일괄 정산 불요구).
- 자리표시 본문 출력 금지(예: `[추후 보충]`, `[TODO]`, `...(생략)...`).

### Soft (권장)

- 도입부에서 가능한 빨리 갈등/위험/강한 감정 진입(권장 첫 200-400자, 120자 고정 아님).
- 미해결 문제나 다음 챕터 기대 앵커를 챕터 말미나 후반부에 배치 권장("후 80-150자"에 한정하지 않음).
- 국면 변화는 리듬감 유지 권장(참고 800-1400자 1펄스, 짧은 챕터는 최소 1회 실질 변화).
- 미시 실현 빈도는 장르 profile 제안에 따라 실행, 기계적 등간격 불요구.

### Style (선택 강화)

- 대화에 가능하면 의도를 담기(탐색/회피/압박/유도), 순수 설명문 줄이기.
- 연속 대형 순수 설명 피하기; 설명이 필요하면, "정보 + 행동/반응"으로 분할 권장.
- "돌아가서 쉬었다"식 기계적 마무리 피하기; 평온한 마무리를 사용할 경우, 동시에 미해결 기대를 유지해야 함.

## 쾌감 포인트와 리듬 (장르 profile에 따라 조정)

- 쾌감 포인트 밀도는 장르와 챕터 유형이 함께 결정: 전환 챕터는 저밀도 허용, 하지만 "전체 챕터 수확 없음"은 불허.
- 조합 쾌감 포인트와 마일스톤 쾌감 포인트는 롤링 윈도우 평가(5챕터/10-15챕터) 사용, 경보용이며 매 챕터 하드 판정 아님.
- 연속 동일 유형 쾌감 포인트가 3챕터 달하면 위험 경보, 유형 변형이나 실행 차별화 수정 우선.

## Strand 균형 경고

| 스토리 라인 | 경고 조건 |
|--------|----------|
| Quest(메인라인) | 연속 5+ 챕터 |
| Fire(감정선) | >10 챕터 미등장 |
| Constellation(세계관) | >15 챕터 미등장 |

## 금지 사항

- `[추후 보충]`, `[TODO]`, `...(생략)...` → 반드시 완전히 작성
- 전투 후 사후 처리 묘사 없음(도시 이능 장르)

1. 챕터 본문 (Step 2A/2B 출력)
2. 심사 보고서 (Step 3 집계 결과)

Step 2B와의 역할 경계:
- Step 2B: 스타일 변환 (표현 레이어)
- Step 4: 문제 수정 (품질 레이어), 심사 문제 수정, Anti-AI 최종 검사, 독소 포인트 회피 포함

Step 2B를 이미 실행했다면, 본 단계에서 전량 문체 개작을 반복하지 않고, "필요한 수정"만 합니다.

## 1. 입력 계약

```json
{
  "chapter_file": "chapters/chapter_0123-챕터제목.md",
  "overall_score": 82,
  "issues": [
    {"agent": "consistency-checker", "type": "POWER_CONFLICT", "severity": "critical", "location": "제6단락", "suggestion": "경지 월권"},
    {"agent": "ooc-checker", "type": "OOC", "severity": "high", "location": "제9단락", "suggestion": "캐릭터 어투 이탈"}
  ],
  "pass": true
}
```

`chapter_file`은 반드시 현재 챕터의 실제 파일 경로여야 합니다. 프로젝트가 제목 포함 파일명으로 아직 마이그레이션하지 않은 경우 `chapters/chapter_0123.md`도 전달 가능합니다.

## 2. 실행 순서 (반드시 순서대로)

1. 심사 보고서의 문제 수정 (먼저 `critical/high`)
2. 웹소설화 Hard/Soft/Style 규칙 검증
3. Phase 1 Anti-AI 최종 검사 및 개작 실행
4. No-Poison 독소 포인트 회피 검사 실행
5. 윤색 결과와 deviation (있을 경우) 출력

## 2A. Anti-AI 탐지 세칙 (실행 순서 3단계 대응)

> 어휘 빈도 통계는 **알림 용도만**으로, 경성 기준으로 더 이상 사용하지 않습니다. 명확히 초과할 경우, 수정하고 간략히 설명해야 합니다.
> 설명: 어휘 빈도가 알림 용도일지라도, 최종 텍스트에 여전히 명확한 AI 템플릿 흔적이 있으면 `anti_ai_force_check`는 여전히 `fail`로 판정해야 합니다.
> 본 절은 실행 요약이며, 완전한 7계층 규칙과 고빈도 어휘 라이브러리는 아래 「Phase 1 보충」 섹션을 참조하십시오. 두 섹션은 함께 실행됩니다.

### 일반적인 AI 흔적

| 특징 | 표현 |
|------|------|
| 문장 구조 정제 | 문장 길이가 비슷하고, 구조가 유사 |
| 패턴화된 어휘 | 첫째, 둘째, 마지막으로, 주목할 만한 것은 |
| 과도한 접속사 | 그러나, 따라서, 게다가를 과다 사용 |
| 감정 평이 | 개성화된 감정 표현 부재 |
| 정보 과밀 | 매 문장마다 정보가 있고, 여백이 부재 |

### 고빈도 어휘 알림 목록

| 유형 | 키워드 |
|------|--------|
| 종합어 | 종합 / 요컨대 / 이로 볼 때 / 총괄하면 |

## 자연화 정도 기준 (권장)

| 지표 | 미달 | 달성 |
|-----|-------|------|
| 머뭇거림 어휘 | < 0.5회/500자 | 1-2회/500자 |
| 불확실 표현 | 0회 | >= 2회/장 |
| 단문 비율 | < 20% | 30-50% |
| 구어체 표현 | 0회/1000자 | >= 2회/1000자 |

> **참고**: 자연화는 많을수록 좋은 것이 아니며, 과다하면 의도적으로 보입니다.

### 강제 실행 프로토콜 (추가)

- 반드시 본 절의 "7계층 규칙 + 고빈도 어휘 라이브러리 + 최종 검사 목록"을 완전히 실행해야 하며, "권고 사항"으로 축소하는 것을 금지합니다.
- 반드시 전문 단락별 검사를 실행해야 하며, 샘플링 검사를 금지합니다.
- Step 4 완료 후 반드시 `anti_ai_force_check: pass/fail`을 출력해야 합니다.
- 결과가 `fail`이면, 반드시 Step 4에 머물며 재작성해야 하고, Step 5로 진행할 수 없습니다.
- 고위험 표현에 해당하지만 줄거리 필요로 유지하는 경우, 반드시 `deviation`에 기록해야 합니다 (위치 + 이유 + 대가).

### 전문 검사 범위 (필수 검사)

- 전문 챕터 단락별 검사
- 모든 대사 차례별 검사
- 장 시작/장 중간/장 끝 모두 Anti-AI 규칙 통과 필수
- 해당 항목이 있으면 반드시 개작하거나 deviation 기록

### 제2계층: 문장 구조 규칙 (반템플릿)

- "첫째/둘째/마지막" 3단식 설명 작법 금지.
- 연속 3문장 "주어 + 서술어 + 목적어" 동일 구조 금지.
- "그는 세 가지를 해야 한다고 생각했다: 1, 2, 3" 리스트화 서술 금지.
- 매 3~5단락마다 최소 1회 문장 길이 변화 (단문 삽입/동작 삽입/대화 반문).

### 제3계층: 형용사와 부사 제한

- 연속 두 개 이상의 형용사가 같은 명사를 수식하면, 기본적으로 재작성.
- 매 300자 중 "매우/극히/유달리/특히/무척" 총수가 4를 초과하지 않도록 권장.
- "동작 + 결과 + 대가" 우선, "추상 평가어" 약화.

### 제4계층: 사자성어/관용어 제한 사용

- 고빈도 공전 사자어 밀집 나열 금지 (예: "심조팽배, 만감교집, 오미잡진" 연용).
- 매 500자 사자 관용어 3개 이하 권장, 연속 출현 불가.
- 성어 사용 시, 반드시 서사 기능을 담당해야 함 (정보 추진/갈등/캐릭터 태도).

### 제5계층: 대화 탈AI화

- "설명서식 대화" 금지 (배경을 완전히 설명, 논리가 과도하게 가득).
- 대화에는 반드시 의도가 있어야 함 (탐색/회피/압박/유도/방어).
- 진짜 구어체 머뭇거림, 끼어들기, 반문 허용, 전원 "표준 서면어" 금지.

### 제6계층: 단락 구조

- 한 문장 단락 비율 25%-45% 권장 (갈등 챕터에서는 높일 수 있음).
- 단락 길이 20-100자 권장, 연속 대단락 설명 방지.
- 장면 전환은 동작/소리/위치 변화 우선, "제1막/제2막" 라벨 사용 금지.

### 제7계층: 문장부호 리듬

- `......` 또는 `!!!` 연속 사용 금지.
- 생략부호, 느낌표 단락당 최대 1회 (특수 감정 폭발점 제외).
- 긴 문장에서 쉼표가 4개 초과 시, 문장 분리 우선.

### Anti-AI 개작 알고리즘 (실행 동작)

1. 추상 감정 문장 → `생리 반응 + 현재 의도 + 다음 동작`
2. 결론 문장 → `사실 디테일 + 대가/리스크 + 결정`
3. 연속 설명 문장 (>=3) → "대화/동작/반문" 혼합 배치로 변경
4. 연속 동일 구조 문장 (>=3) → 최소 1문장을 단문으로 끊거나 동작 앵커 포인트 삽입
5. 대화 전체 단락 배경 설명 → "의도가 있는 대립식 대화"로 변경

### 통과 기준 (수동 판정)

- 전문에 처리되지 않은 3단식 나열 템플릿 문장이 남아있으면 안 됨.
- 전문에서 해당하는 고위험 표현이 모두 개작 또는 deviation 기록됨.
- 최소 3곳에서 "추상 문장→행위 문장" 개작 완료 (전문 범위 내 통계).
- 장 끝에 감지 가능한 다음 단계 압력 또는 미폐합 문제가 존재.
- 고위험 표현을 여전히 유지하는 경우, deviation에 유지 사유 기술 필요.

### Phase 1 최종 검사 (원본 유지)

- [ ] 고위험 어휘 전문 검사 및 필요 교체 완료.
- [ ] 3단식 설명문 (첫째/둘째/마지막) 미출현.
- [ ] 대화에 진짜 갈등 의도가 있고, 정보 전달식이 아님.
- [ ] No-Poison 독소 포인트 레드라인 검사는 제5절 참조 (본 목록은 Anti-AI만 커버).
- [ ] 수정 후 "설정은 곧 물리 / 대강은 곧 법률" 미훼손.

## 3. 심사 문제 수정 우선순위

| 심각도 | 처리 규칙 |
|---|---|
| critical | 반드시 수정; 수정 불가 시 반드시 deviation과 사유 기록 |
| high | 반드시 우선 처리; 수정 불가 시 deviation 기록 |
| medium | 분량과 효익에 따라 처리 |
| low | 선별 처리 가능 |

유형별 수정 동작:
- `OOC`: 캐릭터 화술, 리스크 성향, 의사결정 경계 복원
- `POWER_CONFLICT`: 능력을 합법 경지로 하향, 또는 "획득 경로+대가" 보충
- `TIMELINE_ISSUE`: 시간 경과 앵커 포인트 보충
- `LOCATION_ERROR`: 이동 과정과 공간 앵커 포인트 보충
- `PACING_IMBALANCE`: 누락된 추진 이벤트 추가 또는 잉여 설명 단락 삭제
- `CONTINUITY_BREAK`: 연결 문장과 전환 동작 보충

## 4. 웹소설화 계층 규칙

### Hard (반드시 충족)

1. 본 챕터에 최소 1개의 명확한 추진 포인트 (정보/행동/관계/국면 중 최소 하나).
2. 핵심 대화에서 의도 판정 가능 (탐색/압박/회피/유도 중 최소 하나).
3. 추상 판단문을 "동작/반응/대가" 표현으로 변경.

### Soft (충족 권장)

1. 장 시작은 전반 200-400자 내에 갈등/리스크/강한 감정 진입 권장.
2. 챕터 중반에 리듬 펄스 있음 (800-1400자에 한 파동 참고, 짧은 장은 최소 1회).
3. 후반 또는 장 끝에 미폐합 문제 또는 다음 단계 기대 앵커 포인트 유지.

### Style (챕터 유형별 선택)

1. 연속 대단락 순수 설명 방지, "정보+동작/반응" 교대 우선.
2. 평온한 마무리 허용, 하지만 기계적 중단은 불가.

## 5. No-Poison 독소 포인트 회피 (5유형)

1. 지능 저하 추진: 캐릭터가 오직 줄거리 추진을 위해 상식을 무시.
2. 강제 오해: 한마디면 설명 가능한데 장기간 끌기.
3. 성녀 무대가: 고위험 대상을 경계 없이 용서.
4. 도구인 조연: 기능 노드에서만 등장, 독립적 동기 부재.
5. 이중잣대 판결: 같은 유형의 행위에 평가 기준이 불일치하며 서사적 설명 부재.

독소 포인트 중 하나라도 해당되면, 반드시 "동기/저항/대가" 중 최소 2항을 보충해야 합니다.

## 6. 윤색 레드라인 (돌파 불가)

- 줄거리 방향 변경 불가 (대강이 곧 법률)
- 설정 물리적 경계 변경 불가 (설정이 곧 물리)
- 핵심 복선 삭제 불가
- 캐릭터 관계 기준선 강제 변경 불가

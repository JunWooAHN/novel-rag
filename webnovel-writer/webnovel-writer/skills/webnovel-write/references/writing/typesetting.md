# 조판과 독서 경험 (모바일 우선)

> **목적**: 독자가 "슬라이드하며 읽기" 더 원활하게 (스마트폰 화면), 단락/대화/문장부호 문제로 인한 이탈을 방지.

---

## 1. 단락 규칙 (가장 중요)

- **한 단락 한 동작/한 정보**: 각 단락은 하나의 기능만 담당 (추진/표현/감정/정보).
- **단락이 너무 길지 않게**: 연속 5줄 이상의 긴 단락은, 2-3단락으로 분리 우선 (특히 설명 단락).
- **"빠른 단락"은 클라이맥스에**: 클라이맥스/전투/추격 시, 단문+짧은 단락을 많이 써서 독서 속도와 충격력 향상.
- **"느린 단락"은 복선에**: 복선은 약간 길어도 허용하나, 매 단락마다 새 정보가 있어야 하고, 순수 수식 나열은 안 됨.

---

## 2. 대화 조판 (기본 규범)

- **한 사람 한 대사 한 줄**: 사람이 바뀌면 줄을 바꿈; 같은 단락에 3-4문장 여러 사람 대사를 넣지 않음.
- **대화 사이 동작 삽입**: 동작/표정/환경 삽입으로, 독자가 화자를 식별하고 리듬을 조절하는 데 도움.
- **"누가 말하는지" 혼란 방지**: 다인 장면에서는 2-3문장마다 명확한 화자 또는 동작 앵커 포인트를 보충.

**예시 (권장)**:
```markdown
"확실해?" 이설이 목소리를 낮추었다.

임천이 검은 안개가 용솟음치는 동굴 입구를 바라보며, 목젖이 움직였다: "들어가지 않으면, 답은 영원히 밖에 있어."

"그럼 죽지 마." 그녀가 옥부를 그의 손바닥에 꾹 넣었다.
```

---

## 3. 문장부호와 가독성

- **긴 생략부호/느낌표 남용 자제**: `……!!!` 같은 조합은 한 챕터 내에서 반복 출현하지 않도록.
- **설명 문장이 너무 "논문 느낌" 나지 않게**: "첫째/둘째/요컨대/이로 볼 때" 같은 구조화된 상투어 방지.
- **고유명사 표기 통일**: 인명/세력/경지/기능명은 하나의 버전으로 통일 (`설정집/`에 기입하고 `state.json`에서 추적).

---

## 4. 장면 전환과 챕터 구조

- **카메라 전환 시 숨을 둘 것**: 장면 전환 전후로 각각 빈 줄 하나; 필요시 `---`로 구분.
- **정보 밀도를 보이게**: 핵심 설정/핵심 단서/핵심 전환점은, 가능한 단락 시작 또는 끝에 배치, "반 화면 넘겨야 포인트가 보이는" 상황 감소.
- **후반에 기대 앵커 포인트 권장**: 의문/위협/약속/반전 중 하나면 됨 ("돌아가서 잠들었다" 같은 기계적 마무리 방지).

---

## 5. 발행 전 10항 속찰

1. 대화가 "사람 바뀌면 줄 바꿈"인가
2. 5줄 이상의 긴 단락이 존재하는가 (분리 가능한가)
3. 같은 단락에 여러 캐릭터 대사가 섞여 있는가 (분리 가능한가)
4. "종합/나열 어조"의 설명 단락이 대량 출현하는가
5. 고유명사가 `설정집/`과 일치하는가
6. "???/자리표시자 본문"이 독자에게 노출되는가
7. 장면 전환이 명확한가 (빈 줄/구분선/전환문)
8. 챕터 내 최소 1개의 명확한 추진 포인트가 있는가 (정보/행동/전환)
9. 장 끝에 훅이 있는가
10. 새 엔티티 첫 출현 시 명확하게 쓰였는가 (이름/신분/기억 포인트); 수동 태깅 필요 시 (선택): 숨겨진 XML 태그 사용 (`${CLAUDE_PLUGIN_ROOT}/skills/webnovel-query/references/tag-specification.md` 참조)

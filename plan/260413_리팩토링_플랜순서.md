## 0. 설계 원칙

### 0.1 Clean Code (우선순위 순)

1. **Dependency Inversion**: 구현이 아니라 추상(Protocol)에 의존. 테스트 대역 주입이 가능해야 함.
2. **Single Responsibility**: 한 모듈 = 한 변경 이유. 현재 mixin 4종은 이 원칙으로 재평가.
3. **Command-Query Separation**: 상태를 바꾸는 함수와 값을 반환하는 함수를 섞지 않음.
4. **Pure Domain Core**: `domain/` 레이어는 I/O 없음. 순수 함수·데이터클래스로만 구성 → 테스트가 빠르고 결정적.
5. **명시적 > 암시적**: 전역 싱글톤(`get_config()`, `_client`) 제거. 생성자 주입으로 수렴.
6. **작은 것부터**: 대규모 재작성 금지. 기존 파일명·경로를 최대한 유지한 채 경계만 재조정.

### 0.2 TDD (Red → Green → Refactor)

1. **Characterization First**: 리팩토링 전에 현재 동작을 "있는 그대로" 캡처하는 테스트를 먼저 작성. 버그까지 포함해 고정 → 리팩토링이 의미를 바꿨는지 판정 가능.
2. **테스트 없이는 리팩토링 금지**: 각 Phase 진입 전, 해당 영역 커버리지가 회귀 감지 가능한 수준인지 확인.
3. **테스트 피라미드**:
   - **Unit (domain/)**: 순수 함수, ms 단위, 수백 개. 80% 목표.
   - **Integration (repositories/)**: SQLite 인메모리, 수십 개. 주요 경계 케이스.
   - **E2E (skills/)**: 골든 패스 1~3개. 느리지만 회귀 감지 최후 방어선.
4. **LLM 호출 테스트**: 실제 API 호출 금지. Fixture 기반 fake adapter로 대체.
5. **리팩토링 정의**: 외부 관찰 행위를 바꾸지 않는 내부 구조 변경. 행위를 바꾸려면 그건 "기능 추가" → 별도 커밋/Phase.

### 0.3 코딩 컨벤션 (후속 문서에서 상세화)

- 타입 힌트 필수 (Python 3.11+ 문법)
- Pydantic for 외부 경계(LLM 응답, 파일 I/O), dataclass for 도메인 엔티티
- `Protocol`로 의존성 역전 (ABC 대신)
- 예외는 도메인 예외 클래스(`DomainError`, `SotConflictError` 등)로 래핑

## 1. Phase 순서 개요

| Phase | 이름 | 기간 | 목적 | 선행 조건 |
|---|---|---|---|---|
| **0** | Test Safety Net | 3~5일 | 현재 동작 고정. 회귀 감지 기반 확보 | 없음 |
| **1** | Domain Extraction & Cycle Break | 1주 | 순수 도메인 레이어 신설. 순환 참조 끊기 | Phase 0 |
| **2** | Protocol + DI Container | 1~2주 | 전역 싱글톤 제거. 테스트 대역 주입 가능화 | Phase 1 |
| **3** | Repository Migration | 2주 | 저장소 계층을 Protocol 뒤로 숨김 | Phase 2 |
| **4** | SOT 확장 (DAG/Branch/Provenance) | 2~3주 | 대체역사 인과 모델 + 롤백 기반 | Phase 3 |
| **5** | Fact Extractor Service | 1~2주 | 본문→이벤트 추출 + SOT 대조 | Phase 4 |
| **6** | Web Novel Quality Axis 통합 | 1~2주 | 기존 체커 에이전트를 파이프라인에 결합 | Phase 5 |
| **7** | Cleanup (선택) | 1주 | mixin 정리, dead code, 문서화 | Phase 6 |

**총 예상 기간:** 10~14주 (1인 기준, 본업 병행 시 1.5배)

**핵심 재검토 포인트 (기존 제안 대비 변경):**
- ❗ `DI 컨테이너`가 `Protocol`보다 뒤로 이동했던 초안을 수정 → 실제 순서는 **Domain 추출(Phase 1) → Protocol + DI 동시 도입(Phase 2)**. Protocol 없이 DI만 넣으면 구현체 그대로 주입하는 꼴이라 의미가 없음.
- ❗ `순환 참조 해결`을 별도 Phase로 만들지 않고 **Phase 1 Domain 추출의 자연스러운 부산물**로 처리. 공유 타입을 `domain/`으로 올리면 대부분의 순환이 자동 해소됨.
- ❗ Phase 6 `Web Novel Quality` 통합을 신규 Phase로 추가. 피드백 문서의 "재미없는 소설 양산" 리스크 대응.

## 3. Phase 1 — Domain Extraction & Cycle Break

**목표:** 순수 도메인 레이어 `domain/` 신설. `state_manager ↔ sql_state_manager` 순환 참조를 타입 추출로 끊는다.

**왜 먼저인가:**
- 순환 참조가 있는 상태로 Protocol을 도입하면 Protocol 자체도 순환에 말림
- 도메인 엔티티가 명확해야 다음 Phase의 Protocol 시그니처를 설계할 수 있음

**산출물:**
- `webnovel-writer/scripts/domain/` 신설
  - `events.py`: `SotEvent`, `Scene`, `Chapter` 순수 dataclass
  - `entities.py`: `Character`, `Faction`, `Status` value objects
  - `errors.py`: `DomainError`, `SotConflictError`, `EntityNotFoundError`
- 기존 모듈들이 `domain/`에서 타입 import하도록 수정
- 지연 import (`state_manager.py` line 114, 425) 제거
- Domain 레이어 단위 테스트 (100% 커버리지 목표)

**DoD:**
- [ ] `domain/` 모듈은 다른 프로젝트 파일을 import하지 않음 (독립성 검증)
- [ ] 순환 참조 감지 도구(`pydeps` 또는 수동 그래프) 통과
- [ ] `state_manager.py` · `sql_state_manager.py`에서 지연 import 완전 제거
- [ ] Phase 0 테스트 전부 여전히 green

**상세 문서:** `plan/phase1_domain_extraction.md` (TBD)

## 4. Phase 2 — Protocol + DI Container

**목표:** 전역 싱글톤(`get_config()`, `_client`)을 제거하고, Protocol 기반 명시적 의존성 주입으로 전환.

**산출물:**
- `webnovel-writer/scripts/ports/` 신설 (Hexagonal 용어 차용)
  - `IIndexRepo`, `IVectorRepo`, `ISnapshotRepo`, `IStateRepo` Protocol
  - `IEmbeddingClient`, `ILLMClient` Protocol
  - `IClock`, `IFileSystem` 부수 효과 Protocol
- `webnovel-writer/scripts/container.py`: 경량 DI 컨테이너 (lifetime 관리, override 지원)
- 기존 `config.py`·`api_client.py`의 전역 변수 제거, `Container`의 provider로 이전
- 신규 코드는 **생성자 주입만** 사용. 기존 코드는 호환 어댑터 통해 점진 전환.

**DoD:**
- [ ] 전역 `_client`, `_default_config` 레퍼런스 0건 (grep)
- [ ] 테스트에서 `Container.override(IEmbeddingClient, FakeEmbedder)` 가능
- [ ] 기존 `get_config()` 호출부는 deprecation warning 경유
- [ ] Phase 0 테스트 전부 green

**상세 문서:** `plan/phase2_protocol_di.md` (TBD)

## 5. Phase 3 — Repository Migration

**목표:** 기존 `*_manager.py`를 Phase 2의 Protocol 구현체로 명시. 소비자(skills, services)는 구현이 아닌 Protocol에 의존.

**산출물:**
- 각 manager가 Protocol을 명시적으로 구현한다고 선언 (`class IndexManager: IIndexRepo`)
- 필요 시 인터페이스에 맞게 메서드 시그니처 정리 (이름 동일, 파라미터 명확화)
- 인메모리 fake repo 구현 (`tests/fakes/in_memory_index_repo.py` 등)
- 서비스/스킬 레이어에서 `IndexManager`가 아닌 `IIndexRepo`를 받도록 타입 힌트 수정

**DoD:**
- [ ] `services/`·`skills/` 레이어에서 구현 클래스 직접 import 0건
- [ ] 인메모리 fake로 서비스 레이어 테스트가 SQLite 없이 수행됨
- [ ] Phase 0 + Phase 1 테스트 전부 green

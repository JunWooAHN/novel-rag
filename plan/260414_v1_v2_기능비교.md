# v1 ↔ v2 기능 변화 비교

## 0. 비교의 전제

- **v1은 Claude Code 플러그인**이다. 사용자 진입점은 `/webnovel-*` 슬래시 커맨드이고, 실행체는 `agents/*.md`(**Sub-Agent**) + `scripts/*.py`(도구) + `.env`(설정).
- **v1의 `agents/*.md` 는 단순 프롬프트가 아니라 Claude Code Sub-Agent**다. `tools: Read, Grep, Bash` / `model: inherit` frontmatter를 가지며, 독립 LLM 컨텍스트에서 자율적으로 도구를 호출한다. 이게 v1의 구조적 강점.
- **v2도 Claude Code 플러그인 지위를 유지한다.** 초기 설계(`agents/*.md` → `prompts/checkers/` 1:1 이동)는 Sub-Agent 자율성을 버리는 **퇴화**였고, 플랜 §2.5에서 폐기되어 **3층 분리 구조**로 확정됨:
  1. **Sub-Agent 셸** (`agents/*.md`): v1 자율성·컨텍스트 격리 **보존**. body는 오케스트레이션만
  2. **Python 서비스** (`src/wnw/services/`): 결정론적 백엔드. `mypy --strict` + Result 패턴
  3. **내부 프롬프트** (`prompts/checkers/*.md`): 서비스가 LLM 단발 호출 시 쓰는 템플릿 — Sub-Agent body와는 별개 레이어
- v1 숫자(8 Sub-Agents, 6 checkers, 3-law, Strand Weave 60/20/20 등)는 v2에서 **유지**되고, 변한 것은 **실행 방식**이다. Sub-Agent 지위는 잃지 않는다.

## 3. 에이전트 아키텍처 변화 (⚠ 초기 설계 폐기, 3층 분리로 확정)

### 3.0 초기 설계가 왜 퇴화였는가

초기 v2 플랜의 문장: *"v1 `agents/*.md` 는 `prompts/checkers/` 로 1:1 이동 (텍스트만)"* — 이 설계는 다음 네 가지를 의도치 않게 버리는 퇴화였다.

| 잃을 뻔한 것 | v1 Sub-Agent의 실제 동작 | 초기 v2 "service+prompt" 의 한계 |
|---|---|---|
| **자율 도구 사용** | agent body에서 `Read 본문/*.md`, `Grep state.json`, `Bash webnovel.py status` 를 상황 따라 스스로 호출 | 서비스는 고정 파이프라인. caller가 모든 입력을 미리 조립 |
| **컨텍스트 격리** | Sub-Agent 호출 시 **새 LLM 컨텍스트 윈도우** 할당 → 메인 대화를 토큰으로 오염시키지 않음 | 서비스는 메인 프로세스 메모리 공유 |
| **적응형 검색** | 프롬프트 내부에서 "이 부분 이상하면 추가 Grep 해봐" 식 자가 판단 | 정적 DAG. 검색 경로 고정 |
| **Claude Code 생태계** | marketplace 배포, `Task(subagent_type=…)` 호출, Skills/Agents/Hooks 통합 | 독립 Python 패키지. Claude API 직접 호출로 격리 |

즉 초기 설계는 **"LLM을 stateless API 도구로만 쓴다"**는 선언과 같았고, v1이 Claude Code 플러그인으로 누렸던 이점을 통째로 포기하는 결과였다. 이건 clean architecture의 장점(결정론·타입안전·CI)과 trade-off 관계가 **아니었다** — 두 쪽 다 가질 수 있다.

### 3.1 확정 설계: 3층 분리 (플랜 §2.5)


## 4. 작성 중 사용자 결정이 필요한 설계 포인트

### P1. 개연성 수치의 산출 주체

- (a) Claude가 직접 숫자 산출 — 재현성 문제 큼
- (b) 리트리벌 결과 + Claude 정성 판정을 애플리케이션이 수치화
- (c) 수치 없이 카테고리(high/med/low)

**권장**: (b) 또는 (c). 원 문서는 (a)처럼 읽히지만 확률 40%/80%의 근거가 없음.

### P2. 앵커 계층 구조

- 대형 앵커 1종
- 대형 + 중간 2종 ← **인덱스 §3.4 명시, 권장**
- 더 세분 (3종 이상)

### P3. 보조 사건 "Auto-Creation"의 승인 루프

- 작가 승인 전 `anchor_paths`에 **후보 상태**로만 들어가고 승인 시 확정.
- 원 문서의 "자동 삽입" 뉘앙스는 제거.

### P4. 4종 질의 초안 (제안)

1. `propose_milestones(target_anchor, era_tags)` → 징검다리 후보 N개
2. `assess_gap(anchor_a, anchor_b, era_tags)` → 간극 진단 + 보정 제안
3. `verify_anchor_consistency(anchor_path)` → 원역사와 모순 체크
4. `suggest_auxiliary_event(gap_report)` → 보조 사건 후보

### P5. anchor_paths 스키마 위치

- §0의 3번 확인 사항에 종속.

# 자료·저장·검색 경계

| 층 | 역할과 현재 상태 |
|---|---|
| 공용 원역사 | 출처·불확실성을 보존하는 버전 있는 기준선. 영어 위키백과 텍스트부터 구축할 **목표**다. 작품 때문에 수정하지 않는다. |
| 작품 후보/승인 역사표 | 미승인 경로와 창작 사건은 후보, 작가가 승인한 미래 사건은 잠긴 집필 명세다. 승인 계획은 이미 공개된 사실과 다르다. |
| 작품 공개 정사 | 승인 본문·전표가 단일 작품 브랜치에 반영된 선형 이력이다. 다른 작품에 자동 상속하지 않는다. |
| 보유 소설 코퍼스 | **실행 완료:** 분석 원문 7편을 로컬 SQLite `segments.body`에 적재. 운영 정사나 원역사 DB가 아니다. |

앞 세 층의 의미와 단일 정사 원칙은 [핵심 설계 §4](../systems/README.md#4-원역사와-작품-역사의-경계)에 있다. 네 번째 층의 적재·검증은 [코퍼스 안내](../research/chapter-ingestion/README.md)와 [독립 검토](../research/chapter-ingestion/review.md)에 있다.

**운영 저장 목표는 중앙 PostgreSQL + pgvector**다. 공용 원역사와 작품별 개변을 논리적으로 분리하고, 원역사 전체를 작품마다 복제하지 않는다. SQLite는 현재 원문 분석 코퍼스와 토이·반출·아카이브 후보에 쓰지만 운영 정사를 PostgreSQL과 동시 갱신하지 않는다. HelixDB는 운영 대상이 아니다. PostgreSQL 설치·이관·성능 검증은 아직 완료되지 않았다. [핵심 설계 머리말 및 §4·6](../systems/README.md#6-교체-가능한-기술-변하지-않는-계약), [실행계획 §2](../plans/20260918-current-system-execution-plan-v0-1.md#2-과거-플랜에서-현재-작업으로-바꾸는-기준)

검색은 작품, 원역사 버전, 검토 완료 범위, 기간, 개변 유효성, 공개 상태, 인물의 인지 조건으로 제한한다. **기획자가 볼 기간**과 **장면 인물이 알 수 있는 사실**은 다른 필터다. 역사·상태는 발생/유효 기간, 인물은 활동·관계 기간, 기술은 당시 보급 조건, 과학 원리는 질문과 적용 조건을 기준으로 고른다. 전 역사 top-K 뒤에 기간 밖 결과를 버리는 방식만으로는 부족하다. 범위 확장은 대상·기간·이유를 기록해 검토한다. [핵심 설계 §6 ‘작품 기간과 장면별 검색 범위’](../systems/README.md#작품-기간과-장면별-검색-범위)

Granite 지식 벡터와 Munche 문체 벡터는 별도 공간이다. 벡터는 원문·출처·승인 원장의 파생 검색물이며 사실이나 인과의 증명이 아니다. `novel-corpus.sqlite3`의 `title_sequence`와 `ordinal`도 공식 회차 번호가 아니다. 검증된 번호에는 `chapters`, 미확정 구간에는 `ranges`·`titles`를 사용한다. [핵심 설계 §5–6](../systems/README.md#5-모델과-데이터의-역할), [코퍼스 조회 규칙](../research/chapter-ingestion/README.md#조회)

**조사 계획:** 사용자가 다운로드 완료를 확인한 `wiki-dump/` 텍스트 XML bzip2 19개(로컬 목록 합계 43.26 GiB)를 출발점으로, 불변 출처 snapshot·검토 상태를 추적하는 원역사 assertion 릴리스·최소 개념/관계 계약·재생성 가능한 검색 인덱스의 경계를 조사한다. 키워드, 필터+벡터, hybrid, 명시 관계+hybrid를 동일한 필수 범위 필터 아래 비교하도록 설계하며 실험은 아직 수행하지 않았다. 공식 배포 목록·checksum·파싱 무결성도 미검증이다. [조사 계획](../plans/20260924-history-sot-ontology-research-plan.md), [사전 출처 지도](../research/20260924-history-sot-ontology-source-map.md)

**두 역사층의 대응:** 최근 [설계 문답 정리](../systems/20260924-history-ontology-and-anchor-bridges.md)는 정본 역사 온톨로지와 작품 개변 온톨로지의 상호 분석을 목표로 명시한다. 여기서 두 DB는 논리적 자료층을 가리키며 원역사를 작품마다 물리 복제하는 결정이 아니다. 큰 사건·세부/관련 사건, 포함 관계·인과 관계, 효과 시점을 구별한다. 지정·채택한 전표는 계산 입력 사실이고 시점 이전을 보존하며, 관계가 미기재됐다는 이유만으로 거짓 또는 인과 없음으로 판정하지 않는다. 일반 조회와 의미 검색은 함께 필요하지만 구체 스키마는 미결정이다. [핵심 설계 §4·6](../systems/README.md#6-교체-가능한-기술-변하지-않는-계약)

**항목의 깊이 — 제안:** 이음새가 답해야 할 질문을 실제 역사 작은 구간에 적용하고, 자료·표현·추론 중 무엇이 부족한지 보고 객체·관계를 보탠다. 사건·상태·역할·자원·역량·조건/효과·근거를 후보로 두되 판단과 서사가 달라지는 정보부터 상세화한다. 과학 원리를 아는 것과 해당 지역에서 기술을 만들고 보급할 역량, 필수·대체·촉진·방해 조건은 구별한다. 모든 전표에 모든 필드나 미세 수량을 채우는 완전성 목표는 아니다. 이는 미확정 설계 방법이고 DDL·온톨로지 클래스는 선택하지 않았다. [이음새 통합 문서](../systems/20260924-history-ontology-and-anchor-bridges.md#온톨로지-항목을-정하는-방법--제안)

DB 구축과 번호 대응의 **현재 수치**는 [현재 상태](status.md)에서 확인한다. 역사 설계가 이 자료를 쓰는 흐름은 [시스템](system.md)에 있다.

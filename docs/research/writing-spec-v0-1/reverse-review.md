# 입력 역구성 계약 교차 검토 — 진행 기록

검토일: 2026-09-24. 대상: [입력 계약](reverse-input-contract.md), [후보 정책](reverse-candidate-policy.md). 기준: [핵심 시스템 §1–5](../../systems/README.md), [현행 실행계획 R/A/B](../../plans/20260918-current-system-execution-plan-v0-1.md). 이 검토는 계약의 문서상 일관성 판정이다. 파일럿 원문 구간의 별도 대조 전에는 예제의 수락을 뜻하지 않는다.

## 현재 판정

**계약 문서 자체는 파일럿 작성에 사용 가능하다. 파일럿 예제의 수락은 별도 판정한다.** 계약이 사용자 순서인 작가 비교 → 취향 선택 → 기존 원문 정답 고정 → 입력 역구성 → 대조 → 작은 학습을 명시했고, 검토 레코드와 Writer 입력을 분리한 것은 적절하다. 결과 수준의 필수 계획 사건은 Writer에게 줄 수 있지만 정답 문장·대사·이후 원문·인물에게 없는 미래 지식은 주지 않는 경계도 [시스템 §3·§5](../../systems/README.md)와 맞는다. 개발용 가상 역사표와 실제 승인·잠금 정사를 구별한 점도 맞다.

| 중요도 | 발견·근거 | 필요한 조치·담당 |
|---|---|---|
| **해결됨: 개발 예약과 split** | [실행계획 R §3.1](../../plans/20260918-current-system-execution-plan-v0-1.md)은 후속 학습 split을 **예시·문체 reference 생성 전**에 고정한다. 수정된 계약은 분석한 7편·이전 문맥·파생물과 1588 파일럿을 영구 개발 풀로 예약하고, 이 단계의 계약 JSON은 설계·검수 자료로만 둔다. 후속 학습 예시·reference 생성 전에 개발 풀 내부 split·겹침 정책을 고정하고, reference를 train에서만 만든다고 적었다. 실제 학습 승인과도 분리했다. | 계약·정책의 이 구분은 현행 계획에 합치한다. 후속 학습 패킷을 만들 때 실제 split 기록의 존재를 다시 확인한다. |
| **해결됨: 미확인 지식 예시** | 형태 예시의 `character_knowledge.knows`에서 대상 시작 전 노출 여부가 미확인인 ‘제안받은 선택지’를 삭제했다. 현재는 ‘자신의 현재 형편’만 적고 대상은 `hold`다. | 파일럿의 실제 인지 시점은 `work_ganda_1588` 원문 대조로 별도 검증한다. |
| **유지할 장점** | 후보 정책의 `hold`는 발췌가 장면을 자르거나 이전 문맥이 부족할 때 적용된다. 이것은 고정 글자 수 표본을 곧바로 학습 예시로 삼지 않는 안전장치다. | 파일럿에도 동일 기준을 적용하고 `accept_for_prototype`와 실제 학습 승인·선호 채택을 별도로 기록할 것. |

## 파일럿 대조

파일럿의 네 자료를 받아 원문 사본의 hash·정답 exact slice·앞 문맥 상한·장면 행위 완결·인물별 인지 경계·결과 수준 명세와 표현 누수를 독립 확인했다. 아래 판정은 **개발용 프로토타입 검수**에만 적용한다.

### 후보 경계 예비 대조

`source-audit.md`와 `source-slices.json`의 후보 `[3022,3925)`, 이전 문맥 `[0,3022)`를 보관 원문에서 독립 조회했다. 원본 SHA-256·바이트 크기, 두 범위의 인접성, 두 slice의 UTF-8 SHA-256, 대상의 원본 바이트 시작·끝, 2화 표제 제외가 모두 기록과 맞는다. 게임의 ‘이주하기/포기하기’ 선택지는 target에 있고 이전 문맥에는 없다.

**수정 확인:** 첫 후보 자료는 주인공이 화면에 빨려 들어가는 웹소설식 전개를 떠올리는 예감을 target 시작 전 이미 겪었다고 서술했다. 원문에서는 그 생각이 `[3022,3925)` 안에 처음 나타난다. 담당 Luna가 이를 prior 요약에서 제거하고 target 관찰·지식 경계로 옮겼다. 새 `writer-input.json`에도 이 예감을 선행 지식으로 주지 않는다.

### 역구성 예제 독립 판정

**`accept_for_prototype` — 개발용 설계·검수 예제로 수락. 학습 투입 또는 최종 평가로 수락한 것은 아니다.**

| 점검 | 독립 확인 결과 |
|---|---|
| 원문과 좌표 | 원본 raw SHA-256·바이트 크기, prior `[0,3022)`와 target `[3022,3925)`의 인접성, 두 slice의 UTF-8 SHA-256, target의 byte offsets, 2화 표제 제외가 모두 [source-slices.json](pilot-1588/source-slices.json)과 일치한다. [review-record.json](pilot-1588/review-record.json)의 정답·이전 문맥 좌표도 동일하다. |
| 장면 경계 | 게임 인터페이스 등장 → 진행/중단 선택 제시 → 주인공의 선택과 잠깐의 의심 → 화면의 동의 표시 → 컴퓨터 종료·재가동 실패까지 target 안에서 닫힌다. 이후 실제 이주나 2화 정보는 target 밖이며 예제는 이를 확정하지 않는다. |
| 인지·공개 | 이주/포기 선택지와 웹소설식 걱정은 target 안에만 있고, [writer-input.json](pilot-1588/writer-input.json)의 scene-start 지식에는 없다. 게임 포장 설명과 농장 압박은 prior에 있다. 이후 이동·만남의 결과를 주인공 지식으로 제공하지 않는다. |
| 필수 사건·누수 | Writer 명세는 선택·동의 표시·컴퓨터 작동 실패를 **사건 수준**으로 지정한다. 이는 계획상 이번 장면 결과로 허용된다. 원문 식별 인용·선택지의 정확한 말·정답 경로·좌표는 Writer 입력에 없고, 정답 참조는 검토 레코드에만 있다. 사건의 원인과 다음 회차 결과도 입력에서 보류했다. |
| 자료 지위 | 이미 분석한 작품과 이 예제는 영구 개발 풀이다. 독립 검토 뒤 `review-record.json`과 `writer-input.json`은 개발용 `accept_for_prototype` 상태로 갱신되었다. 이 판정은 사용자 취향 선택·개발 풀 split 고정·실제 학습 승인으로 자동 승격시키지 않는다. |

재사용할 때는 원문 사본 hash와 좌표를 다시 확인하고, 학습 예시·문체 reference 제작 전에 개발 풀 내부 split과 중복/문맥 겹침 정책을 고정해야 한다. 표본 한 장면으로 이 작가의 전체 리듬이나 사용자 취향을 판정하지 않는다.

이 첫 예제는 1화의 **게임 선택과 즉각적 컴퓨터 종료**라는 좁은 사건을 다룬다. 긴 기간의 실제 역사·정치 사건, 역방향 선행 조건 추적, Backfilling으로 만든 중간 사건, 정방향 영향 검토, 승인 역사표의 잠금 집행까지 검증한 것은 아니다. 그 기능의 검증은 별도 사례와 시스템 단계가 필요하다.

# 위키백과 영·한 원문 DB 수직 절편 시험

상태: **작은 실제 실행 완료 · 후보 의미 검토 및 현실 릴리스 미완료**. H200 연결 Storage의 전용 PostgreSQL 16·pgvector DB에 [영어 문종 판](https://en.wikipedia.org/w/index.php?oldid=1372422388)과 [한국어 문종 판](https://ko.wikipedia.org/w/index.php?oldid=41388548)의 원문 revision·main slot을 고정했다. 31B에 입력한 것은 각 페이지에서 고른 **영어 435 UTF-8 bytes, 한국어 146 bytes의 구간 하나씩**이다. 페이지 전문을 모델에 넣거나 전 언어판을 순회하지 않았다. 두 원문 페이지 본문과 선택 구간은 DB에서 revision·byte 좌표·SHA로 구분해 저장했다.

| 실제 처리 | 영어 | 한국어 | 합계 |
|---|---:|---:|---:|
| 고정 원문 페이지 / 선택 구간 | 1 / 1 | 1 / 1 | 2 / 2 |
| Gemma 4 31B 완료 attempt | 1 | 1 | 2 |
| 개별 H 후보, 검토 전 | 4 | 1 | 5 |
| K / B 후보 | 0 / 0 | 0 / 0 | 0 / 0 |
| 정확 인용·UTF-8 범위 연결 / 기계 보류 | 4 / 0 | 1 / 0 | 5 / 0 |
| E5 임베딩 | 1 | 1 | 2 |

두 선택 구간은 죽음·승계 중심이므로 독립 지식 K와 역사적 지식 연결 B의 발생·저장 경로는 이번 실자료에서 시험하지 못했다. F 출처는 영어 덤프 고정 revision과 한국어 API 고정 revision을 **각각** 보존한다. 같은 Wikidata 연결 후보가 있어도 두 문서의 주장이나 인물 표기를 자동 병합하지 않았다. 추출 모델은 `google/gemma-4-31B-it` revision `842da3794eaa0b77d5f08bae87a17459d91ff475`, 검색 모델은 시험용 `intfloat/multilingual-e5-small` revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`(384차원)이다. 두 모델의 역할은 다르며 모델 학습은 하지 않았다.

실제 후보 예로 영어 구간에서 문종 사망은 “Munjong died on 10 June 1452”에 연결됐다. 한국어 구간의 문종 사망 후보는 `1452년 음력 5월`을 원문 그대로 유지했다. 영어 원문의 `10 June 1452`는 달력 체계가 명시되지 않은 날짜 표현이다. 두 표현을 자동 변환하거나 같은 시점으로 확정하지 않았다. 두 언어의 후보는 모두 `candidate_unreviewed`이며 현실 기준선이나 작품 정사가 아니다. 31B 원시 응답 2개, 개별 후보 5행, 원문 근거 좌표와 검토 상태를 DB에서 재조회할 수 있다.

한국어 “문종은 언제 세상을 떠났나?” 질의는 한국어 구간(거리 0.2279), 영어 구간(0.2624) 순으로 고정 출처와 **구간 위치**를 반환했다. “문종 다음으로 왕위를 물려받은 사람은 누구인가?”에서도 **사망 내용만 있는 한국어 구간이 1위**(0.2183), 승계를 포함한 영어 구간이 2위(0.2507)였다. 반환된 `evidence_quote`는 각 구간의 **첫 번째 후보 인용**이므로, 두 번째 질의의 영어 검색 hit에도 사망 인용이 붙는다. 질의에 맞는 승계 근거를 선택한 패킷은 아직 아니다. 이는 두 구간의 벡터 검색과 원문 구간 역추적이 작동한 결과일 뿐, 올바른 의미 순위나 다국어 검색 품질을 입증하지 않는다. 벡터 top-K만으로 사실의 완전성이나 모순 차단을 보장하지 않는다.

독립 검토는 고정 원문→원시 응답→후보→근거 byte span의 연결에서 불일치 0건을 확인했다. **이 검사는 역사적 의미 승인과 별개**다. 영어 원문의 `Grand Prince Seyong` 표기는 다른 자료와 충돌할 수 있어 동일성 검토가 필요하다. “was forced to abdicate”를 `abdicated`로 축약한 후보는 강제성을 잃었고, 한국어 사망 후보는 장소를 사건 object로 둬 역할 정렬이 필요하다. 원문에 있는 패혈증 가능성처럼 원인·불확실성이 이 작은 출력에서 충분히 구조화됐다는 주장도 하지 않는다. 따라서 후보 5건을 전표로 승격하지 않았다.

같은 입력을 다시 실행했을 때 추출은 `requested=0, model_loaded=false`, 임베딩 추가도 0건이었고 DB 건수는 그대로였다. 전용 PostgreSQL **프로세스만** 정상 중지·재시작해 2페이지/2구간/2시도/5후보/2벡터를 다시 조회했다. `pg_dump -Fc`로 33,108-byte 보관판을 만들고 별도 `ontology_trial_restore` DB에 복원했다. 다섯 표의 정렬된 전체 행 값 체크섬과 원문·근거 무결성 검사가 원본과 복원 DB에서 일치했다. 이 시험은 새 컴퓨트 세션에 Storage를 재연결한 검사, NFS 서버 측 sync·장애 내구성 증명, A40 백업을 대신하지 않는다.

[비본문 검증 기록](../../data/analysis/ontology-multilingual-trial-verification.json)에 입력 판·코드 묶음 SHA, 시도·후보·벡터 건수, 검색 거리, 재실행과 복원 결과를 남겼다. 원시 31B 응답과 짧은 선택 구간·개별 후보는 `data/analysis/private/ontology-multilingual-trial/actual-review.json`에 보존했다. [시험 도구 사용법](../../tools/wiki_ontology_trial/multilingual/README.md)에 전용 DB 재시작과 조회 경로를 적었다. 다음 단계는 후보 의미 판정과 다국어 전체 대상 처리장부 확장이며, 이번 결과는 그 완료를 주장하지 않는다.

# 고려, 신대륙에 떨어지다 — 원문 경계 인덱스

의미 분석이 아니라 보관 원문의 구간 경계만 기록한다. 입력은 `docs/references/manifest.json`의 마늘맛스낵 항목 `garlic-snack/고려 신대륙에 떨어지다 [외포완] 1-653.txt`이며 Drive ID는 `12Gc9wGbK6qs7Y7Ai1TlvHWnAUy3qVJi3`다. SHA-256은 `b1f719ca45c171fd28b20d074e3a508946a923b4c8ff64ebd4c0076834d19b82`다. 원문은 `Path.read_bytes().decode('utf-8')`로 읽어 BOM과 CRLF를 보존했다. `start_cp`는 U+FEFF가 code point 0인 전체 디코딩 문자열 인덱스다.

## 검출한 경계

| 경계 형식 | 수 | 처리 |
|---|---:|---|
| 파일 앞머리 | 1 | code point 0의 파일명 줄(선행 U+FEFF 포함)을 `prologue`로 둔다. 다음 표제까지 작품 안내·머리말이 포함된다. |
| `◈ ...` 표제 | 500 | 줄 시작 표제를 `title_section`으로 기록한다. 표제 문자열은 모두 비어 있지 않고 서로 다르며 원문 순서대로 나타난다. 숫자 회차 표기는 없으므로 모든 `number_claimed`는 null이다. |
| 숫자가 적힌 회차 표제 | 153 | 실제 원문에 명시된 501~653화 표제만 `numbered`로 기록하고, `number_claimed`는 해당 표기 숫자다. |
| `[작가의 말]` | 152 | 명시된 후기 경계를 `note`로 분리한다. |
| `ref)` | 1 | 최종 작가 후기 뒤 참고문헌의 시작을 `note`로 분리하며, 마지막 marker부터 EOF까지 보존한다. |

숫자 표제 검색에서 추가로 잡히는 `300화입니다.`와 `400화는 세부 사항 수정 문제로 토요일에 올라갈 예정입니다.`는 기존 원문 점검과 같이 `[작가의 말]` 안의 공지 문장이다. 이들은 회차 표제가 아니므로 경계 marker로 만들지 않았다.

## 앞부분 표제 순번과 번호의 차이

첫 `◈` 표제는 8행 `◈ Universal Kingdoms`, 50번째는 16,224행 `◈ 통일(지도 첨부)`다. 첫 50개는 파일 순서의 표제 순번 1~50으로 경계화할 수 있다. 그러나 그 제목들 자체에 1화~50화라는 숫자가 없으므로 공식 회차와의 대응은 후보 관계로만 남는다. 같은 방식으로 500개 `◈`를 순번 1~500으로 기록하고, 공식 회차 번호를 임의로 채우지 않았다.

마지막 `◈` 표제는 164,028행 `◈ 소비에트 연방`이고, 그 뒤 처음 확인되는 숫자 표제는 164,204행 `501화 소비에트 연방(2)`다. 수량과 순서가 앞부분을 1~500화로 볼 가능성을 뒷받침하지만, `◈` 표제 순번과 공식 회차의 일대일 대응을 증명하지는 않는다. 따라서 JSON에서는 500개 모두 `kind: title_section`, `number_claimed: null`, `confidence: confirmed`로 둔다. `confirmed`는 줄 시작 표제 자체의 확인을 가리키며, 회차 번호 연결은 확인되지 않았다는 내용을 각 marker의 `note`에 명시한다.

명시적 숫자 표제는 501부터 653까지 빠짐없이 연속된다. 653화 표제 뒤에도 본문이 이어진다. 마지막 본문 뒤 `[작가의 말]`은 207,924행에서 시작하고, 참고문헌 marker `ref)`는 207,962행에서 시작한다. 참고문헌 구간은 파일 끝까지 잡아 둔다.

모든 시작점은 원문에서 직접 얻은 code point 위치이며 중복 없이 오름차순이다. 각 `label`은 `text[start_cp:start_cp+len(label)]`와 자동 대조했다. 시작점부터 다음 marker 직전까지, 마지막 marker에서는 EOF까지를 경계로 삼으므로 공백·본문·후기·참고문헌이 사이에서 탈락하지 않는다. 표제 시작 사이 가장 긴 간격은 16,394 code point로 명시 회차 표제 591화와 592화 사이에 있다. 번호 없는 `◈` 표제끼리의 가장 긴 간격은 11,574 code point다. 경계가 불명확한 마지막 잔여 구간은 발견되지 않아 `hold`/`unresolved` marker는 추가하지 않았다.

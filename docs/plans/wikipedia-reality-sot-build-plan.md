# 대체역사 생성용 현실 역사·지식 구축 대상 목록

- 상태: **범위·산출 대상 제안.** 이 문서는 구축할 데이터 집합을 정하는 계획이다. 덤프 검사·서버 접속·추출·DB 적재·현실 역사표 채택은 아직 실행하지 않았다.
- 목표: 영어 위키백과 덤프에서 대체역사 생성에 쓰일 **1949년 말까지의 현실 역사 사건·상태**, **독립 지식 객체**, 둘을 잇는 **등장·인지·확산·사용 기록**을 만든다. 세계 전체를 잠재 범위로 두되 소설의 개변·필요조건·파급을 설명하는 데 쓸모 있는 데이터 집합부터 구축한다. 특정 왕조·전쟁·지역에 범위를 가두지 않는다.
- 구축 장소: 사용자가 지정한 **A40 서버**를 원문 보관·배치 처리·중앙 PostgreSQL+pgvector의 목표 호스트로 둔다. 서버의 CPU·RAM·VRAM·여유 저장 공간·백업 경로·접속 가능 상태는 확인되지 않았다. 로컬은 설계·코드·작은 검증 표본·질의 클라이언트 용도로 제한한다.
- 기존 계약: [현실/작품 공통 시스템 규칙](../systems/README.md), [CIDOC CRM 기반 상세 매핑](wikipedia-history-sot-mapping.md), [입력·근거 보존 계약](wikipedia-history-sot-mapping/ingestion-contract.md). 상세 필드·관계 매핑을 여기서 재작성하지 않는다. **이번 구축 대상은 축소**하되, 매핑 사전의 확장성은 유지한다. 매핑표는 데이터 형식·의미 경계의 후보 사전으로 재사용한다.

## 범위와 우선순위

**1950년은 대략적인 선별 기준**이다. 역사 사건은 실제 발생·유효 시점으로, 인간의 지식 내용판은 정식화·기록·사용 시점으로 판단한다. 자연 현상이나 재료 자체의 존재는 후대 이론·공정의 선행 존재를 증명하지 않는다. 위키 페이지 편집일이나 후대 연구서 출판일이 늦어도 그 안의 옛 사실은 살핀다. 명백한 1950년 이후 사건·내용판은 구축 대상에서 제외하되, 경계에 가까운 주장과 불명 연대는 근거·가능 범위를 기록해 보류 또는 제한 사용하며 작은 날짜 오차만으로 자동 폐기·릴리스 중단하지 않는다.

이것은 이번 목록의 기본 범위 해석이다. 빙의 주인공이 가져올 1950년 이후의 현대 지식을 위한 별도 지식 묶음은 현재 구축 대상에서 제외한다.

인물·국가·기관이 경계 전후에 걸치면 필요한 이전 구간의 사건과 속성을 유지하고, 존재의 시작·종료가 미상이면 미상으로 둔다. 1949년에 임의로 사망·멸망·종료시킨 기록을 만들지 않는다. 장기 사건의 확인된 이전 부분과 이후 부분을 구분한다. 연대가 없는 자연 현상·재료의 **대상 식별**과 인간이 제시한 설명·공정의 **지식판**을 구별한다. 인간 지식의 해당 시대 근거가 불명확하면 근거와 상태를 남겨 검토하고, 개념 객체의 임의 탄생 연도는 생성하지 않는다.

`P0`은 첫 대체역사 질의와 앵커 검증에 필요한 기반, `P1`은 시대·지역·장르 확장을 위한 필수 확대 순서다. 우선순위는 **분야 착수 순서**이며 P0의 전 세계 전량 완료가 P1 착수 조건은 아니다. 실제 첫 시대·지역·작품 묶음은 후속 구축 플랜에서 정한다. `P1`은 영구 제외가 아니다. 각 항목의 예시는 **질의 용도**이지 이 문서가 실제 역사 사실을 채택했다는 뜻이 아니다. 모든 레코드는 `source_id`, 원문 위치, 주장 상태, 유효 시점/시기 불명, 식별·검토판을 공통으로 가진다.

## B. 독립 현실 지식 객체: 시대의 인물과 분리해 식별할 내용

## 문서별 정제 장부와 누락 확인

의미 추출 전에 덤프 원본의 `snapshot → shard → page → revision → slot` 목록과 해시를 **가벼운 독립 XML 인벤토리**로 고정한다. 선별된 slot의 원문은 겹치지 않는 기본 회계 단위로 나눈다. 문단·목록 항목·표 셀·독립 template 필드가 기본 단위이고, 표 행/헤더·인용·inline template·link처럼 중첩되는 구조는 단위의 주석/부모 관계로 남긴다. 빈틈인 markup·공백은 `structural_only` 단위로 표시해 원문 span을 회계한다. 표 행과 그 셀, 문단과 그 안의 인용을 같은 분모에 두 번 세지 않는다. 단위별 의미 후보는 **0개 이상**이며 문서 1개=전표 1개, 문장 수=역사 사실 수라는 등식은 없다.

| 장부 개념 | 최소 기록 | 쓰임 |
|---|---|---|
| `page_inventory` | `snapshot_id`, shard hash, `page_id/revision_id/slot_role`, 원문 hash·byte 길이, 선택/제외 사유 | 의미 추출과 독립된 원본 분모·재처리 입력판 |
| `source_unit` | 안정 `source_unit_id`, 상위 page/revision/slot, 원문 반열린 byte span, 단위 유형·부모/주석, 파서판 | 구조 분모와 원문으로 돌아갈 좌표 |
| `unit_result` | `source_unit_id`, 실행/규칙/모델판, attempt, 최종 커밋 여부, **하나의** 처리 상태와 사유 | 중단·재실행·미지원·0건·실패를 구별 |
| `output_link` | `source_unit_id`↔후보/주장/지식/전표 ID, 근거 span, 후보 판정·릴리스 참조 | 입력이 어떤 산출물로 이어졌는지 역추적 |

검사용 장부는 **문서마다 별도 SQLite 파일을 만들 필요가 없다**. 중앙 PostgreSQL에 같은 논리 구조를 두거나 검토 표본·장부를 **하나의 SQLite**로 내보낼 수 있다. SQLite를 공용 현실 SoT와 독립된 동시 쓰기 정본으로 운영하지 않는다. 안정키는 snapshot·page·revision·slot·span·파서/추출판을 구별하며, 재시도 attempt는 보존하되 집계에는 한 입력·판의 **최종 커밋 결과만** 넣는다.

선별된 slot의 기본 단위는 한 실행판에서 `candidate_generated`, `justified_zero`, `filtered`, `unsupported_deferred`, `failed`, `unprocessed` 중 **서로 배타적인 하나**로 닫는다. 따라서 **원문 단위 수 = 후보가 나온 단위 수 + 정당한 0건 수 + 제외 수 + 미지원/보류 수 + 실패 수 + 미처리 수**다. 후보 *개수*는 단위 수와 다른 층에서 `accepted + rejected + deferred/contested + unreviewed + candidate_processing_failed`로 나눠 센다. 후보 일부를 만든 뒤 오류·중단된 단위는 최종 `failed` 또는 `unprocessed`로 남기고 부분 후보는 attempt 산출로 보존하되 최종 후보·릴리스 집계에서 제외한다. 재개 후 완결됐을 때만 `candidate_generated`를 커밋한다. 예를 들어 가상 문서의 단위 12개 중 5개가 후보 7건을 만들고, 4개가 제외, 2개가 미지원, 1개가 실패하면 단위 회계는 `5+4+2+1=12`다. 이 수치만으로 원문 안의 역사 사실 7개를 모두 찾았다고 판정할 수 없다.

누락 검사는 세 층이다. **전수 기계 검사**는 독립 원본 인벤토리와 page/revision/slot·해시를 대조하고, 원문 span의 빠진 구간·중복 결과·끊어진 근거 ID·미처리 단위를 찾는다. 정규화 전후 문자열 길이의 단순 일치나 모든 주석 span의 비중첩을 요구하지 않고, 변환표와 합법적인 중첩 정책으로 검사한다. **이상 문서 검사**는 긴데 후보 0건, 표/인포박스가 많은데 후보가 적음, 미지원/실패 비율이 높은 문서를 원문으로 다시 본다. **독립 의미 표본**은 시대·지역·문서 형식·분야별로 무작위 층화해 후보 0건뿐 아니라 후보가 나온 단위도 읽어 부분 사실 누락을 찾는다. 필요하면 다른 규칙/모델의 second pass와 비교한다. 같은 추출기가 만든 발견 수를 자기 결과와 대조해 100%를 얻는 검사는 독립 누락 검사가 아니다.

발견한 누락은 `원문 구조 누락 / 후보 의미 누락 / 근거 연결 누락 / 잘못된 제외 / 중복 병합`으로 기록하고 해당 규칙의 영향 범위를 찾은 뒤 같은 유형을 재처리한다. 첫 구현에서 검토 가능한 산출물은 **문서별 원문 목록, 단위별 처리 장부, 이상 문서 목록**이다. 첫 회계 완료는 선택 범위의 원본 page/revision/slot이 모두 목록에 있고, 모든 기본 단위가 처리·0건·제외·보류·실패 중 하나의 최종 결과와 이유를 가지며 `unprocessed=0`이고, 모든 공개 후보의 근거 연결이 유효함을 뜻한다. 이는 **처리 결과 누락 0**이지 **내용 누락 0**의 보증이 아니다. 의미 누락 표본은 보조 진단으로 보고하며 높은 추정 recall 하나를 주요 릴리스 게이트로 삼지 않는다.

## 만들지 않을 것과 입력 처리 경계

명백한 1950년 이후의 사건·제도·전쟁·인구·과학 이론판·공정판은 이번 현실 데이터 제품의 목표가 아니다. 현대 제품의 모델별 세부 사양, 연예·스포츠의 단순 전적, 허구 줄거리·가상 인물을 현실의 행위자로 만들지 않는다. 이전 시대의 문화·체육·저술 활동도 사회·정치·기술 전파에 의미가 있는 경우에는 H13/K14로 들어올 수 있다. 위키백과의 모든 분야·모든 문장을 같은 비용으로 정밀 추출할 목표는 두지 않는다.

원본 덤프는 감사·재처리를 위해 **불변 입력**으로 보존한다. 명백한 후대 내용은 활성 현실 DB의 사건·지식·벡터로 만들지 않는다. 페이지 제목/범주·구조 필드로 낮은 비용의 후보를 찾되 같은 페이지에 섞인 시대와 개념은 문단·표셀·주장 단위로 재판정한다. 한 페이지의 현대 날짜나 현대 직함만 보고 통째로 버리지 않는다. 경계 불명, 부정, 상충, 근거 부족은 `보류` 또는 제한 상태와 원문 위치로 기록하고 결측을 역사적 부재로 바꾸지 않는다. 검색 누락을 ‘당시 존재하지 않았다’로 주장하지 않는다.

위키백과 문장이 인용한 문헌은 우선 **위키 문장에 붙은 인용**이다. 원저작을 직접 읽거나 검증하기 전에는 그 문헌까지 확인한 사실이라고 기록하지 않는다. 위키의 요약 반복·서로 베낀 페이지를 독립 증언으로 세지 않는다. 모델은 출처 문장에 명시된 사실 후보를 만들 수 있지만, 공정의 필요조건이나 개변의 파급 추론은 **모델 가설**로 분리한다. 현실 전표 채택과 작품의 가상 설정·빙의 인물의 미래 지식은 다른 릴리스/분기에 속한다.

## 목록 이후의 구축 순서와 수락 단위

1. **A40 환경·원본 확인:** 실제 호스트의 저장 용량·GPU/CPU/RAM·PostgreSQL 운영/백업 가능 범위를 확인하고, 보유 덤프의 배포판·manifest·checksum·XML 구조를 검증한다. 의미 추출 전에 독립 XML 인벤토리로 문서별 page/revision/slot·원문 해시 목록을 고정한다. 현재 확인된 로컬 관찰은 XML 19개와 체크섬/`_SUCCESS` 파일의 존재뿐이며 덤프의 정합성이나 서버 이전 완료가 아니다.
2. **후보 목록부터 시험:** 여러 시대·지역·분야의 실제 원문을 층화해 기본 단위 장부와 H/K/B/F 후보 연결을 시험한다. 경계 근처·연대 미상 표본에서는 시기 근거와 불확실성 보존을 확인한다. 문종 사망→단종 즉위는 사건 연결의 시험이며 한국어/한글/제철은 지식·실행 구별 사례다. 이 사례들이 세계 범위를 좁히지는 않는다.
3. **선택 범위에서 P0·P1 확대:** 고정한 원본 목록을 재처리 가능한 단위로 나누고 범위 내 후보만 의미 추출한다. 제목 필터만으로 끝내지 않고 혼합 페이지·희귀 서술, 긴데 결과 0건인 문서를 층화·이상 표본으로 감사한다. 문서별 원문 목록·단위별 처리 장부·이상 문서 목록, 후보의 채택/충돌/보류/기각/실패 분모를 따로 공개한다. 시험 통과는 전체 데이터 집합 구축 완료가 아니다.
4. **현실 릴리스와 작품 활용:** 근거와 판정이 있는 H/K/B/F를 중앙 운영 DB의 불변 현실 릴리스로 발행하고 검색색인은 파생물로 만든다. 작품은 현실 ID를 참조하는 별도 분기에 개변 전표를 둔다. 칭기스칸의 아들에 빙의한 현대인이 한국어·한글·제철법을 퍼뜨리는 예시는 **이번 제품에 허용된 1950년 이전 언어·문자·공정판을 쓰는 작품 분기 격리 시험**이며 현실 릴리스에 추가하지 않는다. 1950년 이후 지식판을 이용하는 시험은 현재 대상 밖이다. 작가가 지정한 앵커·역사표 채택·집필 승인 절차는 [핵심 설계](../systems/README.md)를 따른다.

후속 구축 플랜은 이 목록을 바탕으로 **대상별 원문 선별 규칙, 단계별 실제 건수·자원 측정, A40 저장·백업 예산, 의미 품질 기준**을 실측에 맞춰 구체화한다. 이 목록만으로 A40 용량 충분성·처리 시간·완성 범위를 단정하지 않는다.

# Gemma 4 토이 파인튜닝 연습 액션플랜 v0.1

- 작성일: 2026-09-11
- 실행 주간: 2026-09-14 ~ 2026-09-18
- 상태: 실행 전
- 목적: 방향을 결정하는 것이 아니라 머신러닝 학습 과정을 한 번 끝까지 경험한다.
- 기존 `20260908-gemma4-finetuning-plan-v0-1.md`를 실행하지 않는다. 이 토이 실험이 먼저다.

## 1. 이번 주의 성공 정의

다음 한 줄이 성공 기준이다.

> 소형 Gemma 4에 소량의 내 웹소설 원문으로 LoRA를 학습하고, adapter를 저장·재로드하여 base와 다른 출력을 확인한다.

문체 품질이 훌륭할 필요는 없다. 다음 네 가지가 되면 성공이다.

1. 데이터가 tokenizer를 통과한다.
2. 학습이 오류 없이 끝난다.
3. adapter를 저장하고 새 프로세스에서 다시 불러온다.
4. 고정 프롬프트에서 base와 LoRA 출력을 나란히 비교한다.

## 2. 고정할 선택

| 항목 | 토이 실험 선택 |
|---|---|
| 모델 | `google/gemma-4-E2B-it` |
| 방식 | BF16 LoRA SFT |
| 데이터 | 한 작품의 연속된 장면 28개 |
| 정답 | 사용자가 실제로 쓴 장면 원문 |
| 질문 | 직전 문맥 + 짧은 장면 조건 + 소수의 정사 사실 |
| sequence length | 2,048 tokens |
| micro batch | 1 |
| LoRA rank | 16 |
| 학습량 | 최대 30 steps |
| 평가 | 고정 프롬프트 5개를 사람이 비교 |

이 값들은 성능 최적화 값이 아니다. 파이프라인을 한 번 통과시키기 위한 고정값이다.

## 3. 토이 데이터 형식

실제 SQLite를 연결하지 않고, DB가 나중에 전달할 근거 패킷 모양만 문자열로 넣는다.

```json
{
  "messages": [
    {
      "role": "system",
      "content": "주어진 정사와 인물 지식을 지키며 한국어 웹소설 본문만 작성한다."
    },
    {
      "role": "user",
      "content": "[CANON_FACTS]\n- 사실 1\n- 사실 2\n\n[RECENT_PROSE]\n직전 문단\n\n[SCENE_TASK]\n다음 장면을 이어서 작성한다."
    },
    {
      "role": "assistant",
      "content": "사용자가 실제로 쓴 다음 장면"
    }
  ]
}
```

데이터 분리는 시간순으로 한다.

- 앞의 20개 장면: train
- 그다음 3개 장면: validation
- 마지막 5개 장면: test

동일 장면을 여러 조각으로 복제하지 않는다. 질문에는 정답의 대사·비유·첫 문장·마지막 문장을 넣지 않는다.

## 4. 5일 실행 순서

### 9월 14일 월요일 — 환경과 baseline

- H200 세션을 열고 GPU, CUDA, PyTorch를 확인한다.
- 소형 Gemma 4를 다운로드하고 text generation 1회를 실행한다.
- 고정 평가 프롬프트 5개에 대한 base 출력을 저장한다.

완료 조건: 학습 없이 모델 출력 파일이 생긴다.

### 9월 15일 화요일 — 토이 데이터

- 한 작품에서 연속된 장면 28개를 고른다.
- 장면 원문을 answer로 고정한다.
- 직전 문맥과 짧은 scene task를 question으로 만든다.
- JSONL을 읽어 필수 필드와 token 길이만 검사한다.
- 5개 sample을 직접 읽고 정답 표현 유출 여부를 확인한다.

완료 조건: train/validation/test JSONL이 만들어진다.

### 9월 16일 수요일 — LoRA 1회 학습

- BF16, rank 16, sequence 2K로 최대 30 steps만 학습한다.
- loss와 peak VRAM을 기록한다.
- 중간 탐색 없이 마지막 adapter를 저장한다.

완료 조건: adapter 파일과 학습 로그가 남는다.

### 9월 17일 목요일 — 재로드와 비교

- 학습 프로세스를 종료한다.
- 새 프로세스에서 base + adapter를 다시 불러온다.
- 월요일과 같은 평가 프롬프트 5개를 실행한다.
- base와 LoRA 출력을 블라인드로 비교한다.

평가 항목은 세 개뿐이다.

- 내 문장 호흡과 가까워졌는가?
- 요청한 장면을 끝까지 작성하는가?
- 정사 사실을 명백히 위반하는가?

완료 조건: 프롬프트별 base/LoRA/간단 판정이 한 파일에 정리된다.

### 9월 18일 금요일 — 회고와 다음 결정

- 실행 명령, 걸린 시간, peak VRAM, 발생한 오류를 한 페이지로 기록한다.
- 학습 전후 출력 중 대표 사례 2개만 남긴다.
- 다음 실험을 하나만 선택한다.

다음 후보:

1. 같은 소형 모델에서 데이터 질문 품질 개선
2. sequence를 4K로 늘림
3. 실제 `coder3101/gemma-4-31B-it-heretic` 10-step smoke test

## 5. 이번 주에 하지 않을 것

- 31B 전체 데이터 학습
- abliteration 순서 A/B/C 비교
- rsLoRA와 여러 rank 탐색
- continued pretraining과 DPO
- 실제 SQLite/vector DB 연동
- 자동 질문 생성 파이프라인
- MLX 변환과 INT4 품질 비교
- UI, API 서버, 모니터링 시스템
- 완성형 디렉터리·설정 체계 설계

필요성이 확인된 항목만 다음 실험에서 하나씩 추가한다.

## 6. 최소 산출물

```text
experiments/gemma4-toy/
├── data/
│   ├── train.jsonl
│   ├── validation.jsonl
│   └── test.jsonl
├── run.py
├── adapter/
└── result.md
```

파일은 이것으로 끝낸다. 공용 프레임워크나 추상화는 만들지 않는다.

## 7. 중단 기준

- 작은 모델조차 로드되지 않으면 31B로 넘어가지 않는다.
- JSONL과 chat template가 맞지 않으면 학습을 강행하지 않는다.
- 학습이 한 번 성공하기 전에는 hyperparameter sweep을 하지 않는다.
- 품질이 애매해도 end-to-end 과정이 성공했다면 토이 실험의 목적은 달성한 것으로 본다.

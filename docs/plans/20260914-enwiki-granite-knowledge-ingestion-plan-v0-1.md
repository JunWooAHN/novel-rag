- 작성일: 2026-09-14
- 상태: 논의 반영 및 파일럿 계획. 덤프 다운로드·모델 설치·인덱싱·SOTA 호출은 미실시.
- 상위 기준: [핵심 시스템 설계](../systems/README.md). 상세 계약: [통합 아키텍처 v5](../20260914-novel-factory-architecture-v5.md).
- 관련 계획: [Munche 소설 문체 전용](20260914-munche-style-embedding-integration-plan-v0-1.md), [toy-tune 실행 계획](20260914-toy-tune-architecture-and-backendai-bootstrap-plan-v0-1.md)

## 1. 결정과 범위

1. 원역사·과학·인물 자료는 영어 위키백과부터 구축한다. 한국어를 먼저 구축하거나 영어 전체를 한국어로 번역하는 경로는 기본으로 사용하지 않는다.
2. 지식 의미 검색은 Granite 계열로 검증한다. 첫 기준선은 `ibm-granite/granite-embedding-97m-multilingual-r2`, 384차원이다.
3. 대량 인덱싱 전 `ibm-granite/granite-embedding-311m-multilingual-r2`, 256차원과 비교한다. 모델 크기·검색 품질·벡터 저장량을 각각 평가한 뒤 최종 구성을 선택한다.
4. Munche는 소설 원문·생성문의 문체 비교·예문 검색에만 사용한다. 역사·과학·인물 자료는 넣지 않는다.
5. 본문 생성은 Gemma, 기획·검수·추출은 SOTA라는 정책을 유지한다. 원역사 구축은 toy-tune과 별도 책임이며 toy-tune에는 동결 근거 패킷을 제공한다.
6. 지식 구축의 핵심 소비자는 역설계·Backfilling·정방향 인과 검토다. 사건 검색뿐 아니라 출발 상태·선행 조건·자원·기술·인물 관계의 근거를 제공한다. 작품의 창작 사건은 원역사 릴리스에 넣지 않는다.
7. 작품 기간(예: 1453~1600)을 먼저 정하고 해당 기간의 역사·과학·인물과 필요한 이전 배경을 우선 구축·검토한다. 실제 집필은 사용 범위의 미검토 원역사가 없는 상태에서 시작한다. 범위·원역사 릴리스·검토 완료를 기록하고 추가 자료는 검토 후 편입한다. 상세 기준은 상위 아키텍처 §6.3을 따른다.

‘첫 기준선’은 최종 성능 검증이나 운영 도입 완료를 뜻하지 않는다. 전체 영어 덤프·Wikidata 전체 가공을 첫 Gemma 학습의 선행 조건으로 만들지 않는다.

## 2. 수집 대상과 배포본 선택

### 2.1 영어 본문 우선

영어 최신 본문 snapshot을 원자료로 확보하고 그 안에서 역사·과학·인물·기술·지리 자료를 선별한다. 원문 보관 범위와 SOTA 가공 범위는 별개다. 한국어·중국어·일본어는 작품에 필요한 보완 자료로 추가한다. Wikidata ID로 언어별 문서를 연결하되 다른 언어의 원문·revision·모순된 주장은 덮어쓰지 않는다.

공식 MediaWiki Content File Exports의 `mediawiki_content_current`를 기본 경로로 한다. `history`는 역사 분야가 아니라 편집 이력이다. 구 XML 덤프 배포 경로는 deprecated로 안내되므로 신규 다운로드는 새 배포 경로를 우선한다. [공식 배포 안내](https://wikitech.wikimedia.org/wiki/MediaWiki_Content_File_Exports)

- 날짜가 고정되고 `SHA256SUMS`가 존재하는 완료 배포본을 선택한다. 특정 날짜의 다운로드 가능 여부·파일 크기는 실행 시 확인한다.
- manifest에 출처 URL, wiki ID, snapshot 날짜, 파일 목록·checksum·크기를 기록하고 다운로드 후 검증한다.
- 재시도·부분 다운로드를 지원하되 완료·검증된 파일만 소비한다. 원본 압축 파일은 변경하지 않는다.
- 다운로드는 식별 가능한 User-Agent와 서버 제한을 준수한다. 현재 공식 안내는 IP당 최대 3개 연결을 명시한다. [다운로드 정책](https://dumps.wikimedia.org/)
- 덤프 파일은 사용자가 하나씩 다운로드한다. 후속 적재기는 지정한 완료 파일을 등록·검증하고 페이지/revision 단위로 재개·중복 방지한다. 전체 배포본 중 실제 반입 범위를 기록하며 아직 없는 문서를 역사적 부재로 해석하지 않는다. 이미지는 후속 범위다.

### 2.2 보조 자료

문서 ID·namespace·분류·넘겨주기·Wikidata 연결 정보를 함께 확보한다. 필요 후보는 `page`, `categorylinks`, `linktarget`, `page_props`, `redirect`이며 실제 제공 여부와 스키마를 배포본에서 확인한다. 보조 snapshot과 본문 snapshot이 다르면 날짜 차이·누락 참조를 기록하고 완전히 일치하는 snapshot이라고 주장하지 않는다.

분류만 무제한 재귀 탐색하지 않는다. 시작 분류, 깊이·문서 수 상한, 제외 목록, 작품별 인물·지역·기술 목록, 필요한 문서 링크를 조합한다. 최신 `categorylinks`의 `linktarget` 연결 등 스키마 변경을 고려하고 오래된 컬럼을 고정하지 않는다. [공식 분류 스키마](https://www.mediawiki.org/wiki/Manual:Categorylinks_table)

Wikidata는 필요한 항목부터 반입하고 전체 처리 필요 시 공식 JSON 덤프를 스트리밍한다. 원배열 경계·쉼표를 처리하는 파서를 사용하며 파일 전체를 메모리에 올리지 않는다. qualifiers·references를 생략하는 `truthy` RDF만으로 시간·출처 원장을 구성하지 않는다. [Wikidata 덤프 안내](https://www.wikidata.org/wiki/Wikidata:Database_download)

## 3. 원문·지식·문체를 분리하는 파이프라인

```text
영어 위키백과 최신 본문 + 필요한 Wikidata/보조 자료
    → 원본 snapshot 보존·checksum 확인
    → 문서·절·표·링크·출처 파싱
    → SQLite 문서 카탈로그·키워드 검색
    ├─ 선택 구간 → Granite 의미 인덱스 → 검색 평가
    └─ 선택 자료 → SOTA 추출 → 검증·사람 교정 → 구조화 원역사 릴리스
                                                     ↓
                           구조화 필터 + 키워드 + 의미 검색
                                                     ↓
                         검증된 사실 패킷 → SOTA 기획 / Gemma 집필

소설 원문·생성문 → Munche → 문체 평가·참고 예문 패킷 (별도 경로)
```

SOTA 추출 전의 문서 검색 결과는 ‘원자료 근거 후보’이고, 검증·승인된 구조화 사실과 구분한다. 전체 자료를 먼저 SOTA로 처리하지 않아도 검색 파일럿을 실행할 수 있다. 파싱·적재는 CPU/I/O 작업, 임베딩은 별도 배치 작업으로 두고 H200 세션과 결합하지 않는다.

SOTA는 지정 자료의 사건·관계·시간·기술 조건을 추출한다. 원문 hash, 추출 schema/model/prompt revision으로 처리 결과를 식별해 동일 입력 재작업을 줄인다. 외부 전송 범위와 비용·재시도 상한을 명시하고 실패한 문서는 미처리 상태로 남긴다.

### 3.1 역사 설계 엔진에 제공할 데이터

자료 선정은 특정 앵커를 검토하는 데 필요한 인물·지역·제도·생산·운송·기술 조건에서 출발할 수 있다. 원역사 릴리스는 특정 결말을 정당화하려고 교정하지 않는다. 추출된 주장과 근거, 수락·보류·교정 결정을 구분하고 상충하는 주장은 함께 보존한다.

- 사건 전후의 상태, 행위 주체, 필요한 자원·준비 기간·제도적 조건을 연결한다.
- `requires`, `enables`, `prevents`, `consumes`, `produces`, `changes` 관계는 출처의 명시적 주장인지 SOTA 해석인지 구별한다. 시간적 선후나 문서 링크만으로 인과를 확정하지 않는다.
- 원문 인용 범위가 실제 존재하는지 프로그램으로 검사하고 의미 타당성은 별도로 검토한다. 위키 문서에 참고문헌이 있다고 해당 원저를 직접 확인한 것으로 기록하지 않는다.
- 절은 원문 구조, chunk는 검색 모델에 따른 파생 구간이다. 모델을 바꿔 chunk가 달라져도 사건·조건의 근거를 원문 revision과 범위로 추적한다.
- 기획 엔진은 이를 읽고 작품별 보조 사건을 창조한다. 그 사건과 창작 가정은 작품 계획에만 저장하고, 작가 승인 후 잠긴 집필 명세로 사용한다.
- 부족한 조건·모순·미확인 사항을 반환한다. 인과 확률·임팩트 등급·개연성 점수는 추출 schema에 넣지 않는다. 실제 날짜·단위·출처 있는 수량은 보존한다.

## 4. 과학과 역사의 의미 구분

| 자료 | 표현해야 할 의미 |
|---|---|
| 역사 사건 | 발생 시간·장소·관련 인물·출처·불확실성 |
| 인물·기관 상태 | 생존·직위·소속 등의 유효 기간 |
| 과학 원리 | 설명·적용 조건·출처. 과거 인물의 지식과 동일시하지 않음 |
| 기술의 역사 | 발견·발명·전파·실제 보급 시점과 지역 |
| 기술 구현 조건 | 재료·공정·설비·인력. 출처 사실과 SOTA 추론을 분리 |
| 작품의 기술 도입 | 작품별 승인 계획·역사전표·인물 인지에 속함 |

예를 들어 현대 문서에 증기기관이 설명되어 있어도 과거 인물이 그것을 알고 제작할 수 있다는 뜻은 아니다. 과학 지식을 원역사 사건처럼 임의 연도로 고정하거나 미래 기획을 공개 정사로 승격하지 않는다.

원문·정제 본문·한국어 요약·구조화 사실을 별도 표현으로 보존한다. 페이지·revision·절·범위·hash·출처 URL·사용 조건을 연결한다. 표의 단위·주석·수식은 파싱 과정에서 버리지 않고 처리 실패를 표시한다. 분류·본문·템플릿의 모든 정보가 단순 정규식으로 추출된다고 가정하지 않는다.

## 5. Granite 후보와 비교 이유

97M R2는 384차원, 최대 32,768토큰 입력의 다국어 검색 encoder이며 영어·한국어가 강화 지원 언어에 포함된다. 정확한 한국어→영어 역사 검색 성능을 보장하는 것은 아니다. [97M 공식 카드](https://huggingface.co/ibm-granite/granite-embedding-97m-multilingual-r2)

| 구성 | 출력 차원 | 제작자 보고 다국어 검색 점수 | float32 벡터 100만 개의 순수 용량 |
|---|---|---|---|
| 97M R2 기준선 | 384 | 60.3 | 1.536GB |
| 311M R2 차원 축소 비교군 | 256 | 64.7 | 1.024GB |

점수는 논문의 MTEB 다국어 검색 평가 결과이며 우리 자료의 정확도나 합격 기준이 아니다. 용량은 `개수 × 차원 × 4바이트`로 계산한 십진 GB이며 DB/index·메타데이터·원문을 제외한다. 311M은 계산할 모델이 더 커도 저장할 벡터는 더 작을 수 있다. [논문 본문 및 Matryoshka 평가](https://arxiv.org/html/2605.13521v1)

311M은 256/384 등의 Matryoshka 차원을 지원하지만 97M은 지원하지 않는다. 97M 벡터를 임의로 잘라 같은 효과를 기대하지 않는다. 초기에는 97M/384와 311M/256 두 구성만 비교하고 필요할 때 311M/384를 추가한다. 차원 축소 후 정규화·cosine 계산을 검증한다. [IBM 공식 모델 저장소](https://github.com/ibm-granite/granite-embedding-models)

작은 모델이 모든 300M급 모델보다 좋다거나 긴 입력 지원이 문서 전체를 한 벡터로 저장해야 한다는 의미로 해석하지 않는다. 모델 크기·배치 처리 속도·온라인 query 지연·인덱스 크기·검색 품질을 별도 측정한다. Mac/ONNX 등의 실행 지원도 실제 환경에서 검증하며 Gemma의 MLX 지원으로 Granite 지원을 추정하지 않는다.

## 6. 분할·검색·저장 계약

- 영어 원문에 문서 제목·절 경로를 붙이고 512~1,024토큰 구간을 초기 실험 범위로 삼는다. 이는 우리 시작 설정이며 모델의 필수 규격이 아니다. 비교군은 동일한 원문 범위로 분할하고 각 tokenizer의 초과 길이를 검사한다.
- 문단·표 경계를 보존하고 overlap은 필요한 경우에만 설정한다. 검색 후 부모 절이나 앞뒤 구간으로 확장할 수 있도록 source span을 기록한다.
- 정제·정규화·prefix·pooling·차원 축소·출력 정규화·dtype·model/tokenizer revision을 `embedding_space_id`에 반영한다. query와 문서가 같은 검증된 encoding 계약을 사용하게 한다.
- 한국어 직접 질의→영어 자료 검색과 SOTA 영어 질의 보완을 별도 조건으로 평가한다. 영어 FTS에는 영어 검색어·별칭을 제공하며 한국어를 자동 번역한다고 가정하지 않는다.
- 연도·인물·과학 용어·화학식은 구조화·키워드 검색으로 보완한다. 벡터와 키워드의 원점수를 그대로 더하지 않고 결합 순위 정책을 명시·평가한다.
- 작품 기간·사용 범위 revision·이번 검색 기간, 원역사 revision, 작품별 override, 시점·인지 범위 필터는 벡터 점수와 독립적으로 적용한다. 조사·RAG는 기간으로 후보 집합을 먼저 제한하고, 기간 이전부터 유효한 상태·인물·기술과 관련 과학 원리를 포함한다. 날짜 기준은 자료 유형별로 상위 아키텍처 §9.1을 따른다. 검색 근거의 권위는 원문·검증 상태에 있고 encoder에 있지 않다.
- 사실·원문 구간에 시간·범위 메타데이터를 연결한다. 기간 안팎의 사실이 섞인 문서나 연대 불명 자료를 문서 대표 연도만으로 일괄 판정하지 않는다. 범위 밖 자료는 대상·기간·이유를 기록해 필요한 만큼 확장 조사하고 검토 후 집필에 편입한다.
- 선택된 영어 근거만 필요 시 한국어로 요약한다. 번역/요약은 원문을 덮어쓰지 않으며 사용한 SOTA와 근거 범위를 기록한다.
- Granite와 Munche, Granite 97M과 311M, 다른 차원·revision은 별도 index다. 서로 다른 공간의 벡터를 비교하거나 인덱스 안에서 혼합하지 않는다.

SQLite-vector를 초기 저장 adapter 후보로 유지한다. 파일 artifact/정확 검색에서 시작해 대량 인덱스 방식을 검증한다. `SemanticEncoder`는 지식 구축·검색 영역의 port, `StyleEncoder`는 소설 문체 영역의 port로 분리한다. 공통 파일 manifest를 재사용할 수 있지만 SQL·tensor·호스트 접속을 domain에 노출하지 않는다. PostgreSQL 교체 때도 source ID·필터·공간 식별·snapshot 의미를 유지한다.

## 7. 파일럿과 완료 조건

| 단계 | 범위 | 완료 조건 |
|---|---|---|
| K0: 배포본·원문 | 완료된 영어 current 배포본 선택·확보, parser 표본 검사 | 파일 checksum, 크기·여유 디스크, 절·출처·표 보존 확인 |
| K1: 검색 집합 | 영어 역사·과학·인물 문서 1,000~3,000개, 동일 구간 묶음 | 선정 manifest, 중복·출처·분할 통계, 키워드 검색 기준선 |
| K2: encoder 비교 | 97M/384와 311M/256, 실제 집필 질문 50~100개 | 정답 근거의 Recall@10·순위·검색 지연·처리량·용량 비교 |
| K3: 사실·조건 연결 | 필요한 문서만 SOTA 추출, 상태·선행 조건·자원·관계와 인지/시점 fixture | 출처 일치·해석/창작 분리·패킷 재현, 작은 역설계의 간극·정방향 영향 근거를 추적, 비용 검토 |
| K4: 확대 | 채택 구성으로 범위 확대, 재개·새 릴리스 전환 | 고정 모델·분할·인덱스 설정, 부분 실패 복구, 과거 릴리스 보존 |

질문에는 한국어→영어와 영어→영어, 같은 이름의 다른 인물, 다른 시대의 같은 기술, 숫자·단위·인과 조건을 포함한다. 관련 없는 근거도 반환될 수 있으므로 무응답 질문을 추가한다. 정답 근거는 SOTA 제안만으로 확정하지 않고 사람이 검토한다. 설정 조정용 질문과 최종 확인 질문을 분리한다.

기간 제한 검증에는 시작일 이전 출생자의 기간 내 활동, 기간을 걸쳐 지속되는 제도·기술, 현대 출처의 과학 원리, 연대 불명 자료, 범위 밖 배경의 명시적 확장, 혼합 시대 문서의 구간 선별을 포함한다. 작품 기간 안의 미래 사실도 현재 인물의 지식에 섞이지 않는지 확인한다. 전역 검색과 기간 제한 검색의 근거 회수율·탐색량·지연을 비교하며, 범위 확대 전의 미검토 자료가 집필 패킷에 들어가면 실패로 판정한다.

검색 평가에서는 참조 근거가 검색 corpus 안에 있어야 한다. 여기서의 누수 통제는 질문의 정답 문구를 질의로 복사하거나 test 결과로 설정을 반복 선택하지 않는 것이다. 소설 문체 reference의 train-only 규칙을 그대로 적용해 검색 정답 문서를 corpus에서 제거하지 않는다.

합격 임계값·처리 예산은 첫 표본의 비용과 실패 사례를 보고 정한다. 모델 선택의 근거를 남기고 영어 전체를 먼저 임베딩한 뒤 모델을 다시 고르는 순서를 피한다. K 단계는 Gemma 토이 학습·Munche S 단계와 독립적으로 진행할 수 있다.

## 8. 운영·보존과 미결정 사항

압축 원자료, source manifest, 승인 구조화 릴리스는 보존 대상이다. 벡터·검색 인덱스는 원자료와 고정 설정에서 재생성할 수 있는 파생물이다. 데이터는 Git 밖 지정 workspace에 두고 영구 저장 용량을 확인한 뒤 반입한다. 검증되지 않은 네트워크 파일시스템에 활성 SQLite WAL DB를 두지 않는다.

원문과 문서 URL·revision·라이선스 정보를 함께 보존한다. 위키백과 본문과 Wikidata 구조화 데이터의 조건은 다르며 초기에는 이미지 수집을 제외한다. 외부 SOTA 전송과 재배포 범위를 별도 확인한다. [Wikimedia 이용 조건 안내](https://dumps.wikimedia.org/legal.html)

미결정: 실제 배포 날짜·파일 크기·저장 위치, 최종 자료 범위, parser/보조 덤프 조합, tokenizer/runtime 버전, 97M/311M 최종 선택, SOTA 호출 예산·전송 범위, 검색 합격 임계값. 현재 이 문서는 파일럿 기준이며 다운로드·모델 실행·DB 변경을 수행한 기록이 아니다.

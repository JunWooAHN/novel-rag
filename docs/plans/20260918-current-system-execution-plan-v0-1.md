# 현행 시스템 통합 실행계획 v0.1

- 작성일: 2026-09-18
- 갱신일: 2026-09-24. 선호 작가 4명의 보유 원문 7편 분석·작가별 검토 완료와 집필 기준·입력 역구성 초안 작업을 반영.
- 상태: 현행 설계에 따른 실행 순서 제안. 원문 7편 보관·작품별 Luna 분석·작가별 Sol 검토는 완료. 작가 비교·집필 기준 초안·역구성 계약은 [이번 작업](../research/writing-spec-v0-1/README.md)에서 작성·검토 중이며 사용자 취향 채택과 실제 학습은 미완. R 전체 완료로 표시하지 않는다. 소스 확인·로컬 부분 검사 기록은 2026-09-18 기준이며 아래 구현 단계의 실행 완료를 뜻하지 않는다.
- 설계 기준: [핵심 시스템 설계](../systems/README.md)
- 상세 계약: [아키텍처 v5](../20260914-novel-factory-architecture-v5.md)
- 목적: 제공된 소설의 서사·인물·문체 분석으로 집필 명세와 학습 기준을 정하고, 작은 학습 실험과 기간 기반 역사 설계를 연결해 집필·정사 반영까지 검증한다.

## 1. 출발점

2026-09-18에 읽은 소스·구현 문서 기준이다. 과거 플랜의 완료 표시는 현재 구현의 증거로 사용하지 않는다.

## 2. 과거 플랜에서 현재 작업으로 바꾸는 기준

| 과거 전제 | 현재 실행 기준 |
|---|---|
| 기존 집필 도구 전체 기능을 새 폴더에 이식 | 첫 장면 완주에 필요한 기능부터 구현. 기존 도구는 재사용 후보 |
| HelixDB·여러 그래프 인스턴스 | PostgreSQL + pgvector, 관계 테이블·제한된 관계 탐색 |
| SQLite 운영부터 시작한 뒤 PostgreSQL로 이전 | 파일 기반 토이 실험 후 운영 DB는 PostgreSQL로 구현 |
| 전 역사 구축·검색을 먼저 완성 | 작품 기간·관련 자료를 먼저 지정하고 그 범위에서 구축·조회 |
| 중간 사건을 Writer의 가이드로 사용 | 승인한 모든 계획 사건을 제약으로 집행 |
| 인과 확률·등급으로 경로 선택 | 조건·근거·간극·부작용과 작가 선택으로 경로 결정 |

학습은 기존 `toy-tune`을 확장한다. 지식 구축·작품 관리·정사 쓰기를 학습 패키지에 합치지 않는다. 새 운영 코드의 패키지 경계는 첫 사용 사례에서 정하고, 필요한 domain/application/adapter만 만든다. GUI·상시 에이전트·다중 서버는 첫 완주의 필수 산출물이 아니다.

## 3. 실행 순서와 완료 조건

**R의 원문 분석을 먼저 진행해 무엇을 기획·집필·평가할지 정한다.** 단계 0의 로컬 준비는 분석을 지원하는 병행 작업이다. 이후 학습 실험(A)과 역사 시스템(B)은 독립적으로 준비할 수 있으며 C의 장면 실현에서 연결한다. 전체 역사 DB 구축을 A의 첫 저장·재로드 실험의 선행 조건으로 두지 않는다.

| 단계 | 실제 할 일 | 완료 조건 | 의존 |
|---|---|---|---|
| R. 소설 분석 | 지정한 4명 작가의 보유작부터 작품별 Luna가 구조 지도와 초·중·후반 대표 장면을 분석하고 작가별 Sol이 근거를 검토. 루트는 오케스트레이션만 수행 | 원문 위치가 연결된 작품별 분석, Sol 검토 기록, 작가별 반복 특징·작품별 차이, 채택할 서사/문체 기준과 장면 명세·학습 예시 후보. 분석 범위·누락 표시 | 사용자 제공 원문·목록·범위 |
| 0. 로컬 기준선 복원 | 독립 venv에 `toy-tune[test]` 설치, 전체 검사, 합성 입력의 준비·재검증 | 스키마 포함 전체 검사 통과, 데이터셋 재조회·checksum 확인, 실행 환경 기록 | R과 병행 가능 |
| A1. 작은 Gemma 학습 | 분석 결과에서 선택 원문·명세·평가 기준을 정하고 실제 H200 환경과 모델 revision 고정, tokenizer/mask·engine 구현, baseline→짧은 학습→저장→새 프로세스 재로드 | 실제 파라미터 갱신·정답 loss 범위·재로드 추론 확인, 같은 입력의 전후 결과 보존 | R, 0, 모델·H200 입력 |
| A2. 문체 평가 | Munche 소량 비교와 사람 평가, 가능한 조건에서 동일 입력의 SOTA 비교 | split·예문 누수 통제, 문체·명세 준수·복제·비용을 구분해 채택/보류 기록 | A1의 출력. 원문 분석 준비는 먼저 가능 |
| B1. 최소 계약·사례 | R의 결과로 장면의 목표·갈등·선택·대가·정보 공개와 역사표를 연결. 기간·검토 범위·계획·인지·패킷의 합성 사례와 §4의 미결 규칙 확정 | 정상/차단 사례의 기대 결과가 명확하고 학습 입력·집필 입력의 의미가 일치 | R, 0. 합성 기술 검사는 먼저 준비 가능 |
| B2. 기간 기반 조회 | PostgreSQL에 합성 원역사·작품 상태 적재, 작품/기간/인지 필터와 패킷 생성·반입 구현. 선택 영어 자료로 Granite·pgvector 비교 | 기간 밖·다른 작품·미검토·허용되지 않은 미래 정보 제외, 필요한 과거 상태 포함, 검색 범위·revision 재현 | B1 |

| C2. 실제 작품의 한 화 | 확정한 작품 기간의 원역사·필요 배경 검토 완료, 실제 앵커·역사표 승인, 한 화 집필·검수·선택한 공개 방식으로 반영 | 본문·계획 사건·근거·전표·승인/공개 이력 추적, 해당 작품에 미검토 원역사 없음 | C1, 실제 작품·자료·공개 방식 |

합성 사례의 B/C1 성공은 실제 역사 검토 완료가 아니다. 예시로 나온 1453~1600은 아직 실제 작품 기간으로 확정하지 않는다. 작은 기간의 모의실험으로 기능을 검증해도, 실제 작품이 1453~1600 전체를 사용한다면 그 전체 사용 범위의 검토 완료가 C2의 시작 조건이다.

기간 검색은 자료 유형별 시간 규칙을 적용한다. 이전부터 유효한 제도·기술, 시작일 이전 출생자의 활동, 현대 출처의 과학 원리, 연대 불명 자료, 제한적 범위 확장을 검사한다. 전체 corpus의 top-K에서 뒤늦게 기간을 걸러내는 방식만으로 구현하지 않는다. 필수 계획 사건·금지 조건은 검색 순위와 무관하게 패킷에 포함한다.

### 3.1 R 단계의 분석과 산출물

선정 단위는 사용자가 지정한 **리첼렌·간다왼쪽·명원·마늘맛스낵 작가**다. 10~20편이라는 초기 수량보다 이 작가들의 보유작을 우선한다. Sol 하나가 작가 한 명의 검토를 맡고 Luna 하나가 작품 한 편의 분석을 맡는다. 사용자가 확정한 첫 분석 범위는 구조 지도와 초·중·후반 대표 장면이며 전 회차 정독 분석으로 표시하지 않는다. [작가별 배정·산출물](../research/author-study/README.md)에서 진행 상태를 관리한다. 보유작이 한 편인 작가는 작품 간 반복성을 아직 검증할 수 없음을 표시한다.

첫 입력은 작품명·작가·장르·파일 형식·제공 회차·완결 여부와 원문이다. 판매·순위 정보가 제공되면 출처와 함께 별도로 기록한다. 각 작품의 문단·대사·회차 순서와 원문을 보존하고 회차·장면·원문 범위로 분석 근거를 연결한다. 일부 회차만 있으면 전체 작품의 구조나 결말을 읽었다고 표시하지 않는다.

| 분석 대상 | 확인할 내용 | 시스템에 사용할 결과 |
|---|---|---|
| 작품·에피소드 구조 | 도입의 약속, 목표와 장애물, 위기·전환·보상의 배치, 결말과의 연결 | 역설계·에피소드 기획 기준 |
| 인물·관계 | 욕망·두려움·이해관계, 갈등, 선택과 대가, 관계·태도 변화 | 장면의 동기·갈등·변화 명세 |
| 회차·정보 공개 | 독자가 아는 것과 인물이 아는 것, 질문의 제기·해소, 복선·회수, 회차 말미 연결 | 공개 정보·긴장·보상 설계와 검수 항목 |
| 장면·문체 | 시점, 대사·서술·내면 묘사, 문장·문단 리듬, 어휘, 사건을 장면으로 만드는 방식 | 작가별 문체 프로필, 참고 예문·학습 구간 후보 |

진행은 작품별 구조 지도 → 주요 전환·대표/예외 장면의 상세 분석 → 작품 간 비교 → 작가의 채택 판단 순서다. 모든 원문을 한 번의 요청에 넣지 않고 회차·장면별 분석을 작품 단위로 종합한다. 요약·해석에는 원문 위치를 남기고 대표 표본을 사람이 대조한다. 관찰된 기법, 예상 독자 효과, 실제 독자 반응·판매 정보는 별도 항목으로 둔다.

산출물은 작품별 분석 카드·서사표, 근거가 연결된 장면 분석, 작품 간 공통점·차이·반례 비교표, 채택할 기법·문체 기준, 장면 명세→원문 정답의 학습 예시 후보다. 줄거리·표현을 복제하는 템플릿으로 만들지 않고 새 인물·사건에도 적용할 수 있는 기능을 추출한다. 서로 다른 작가의 문체를 한 평균으로 합치지 않는다. 작품별 장르·연재 단계가 다르면 같은 조건끼리 비교한다.

흥행작만 분석한 결과는 그 집합의 공통점과 차이를 보여준다. 공통 기법이 판매 성공을 일으켰다고 확정하지 않으며, 보편적인 빈도·분량·성공 점수를 만들지 않는다. 독자 반응이나 비교 작품이 필요해지는 주장은 별도 검증 가설로 남긴다.

분석에 사용한 작품은 개발 자료로 취급한다. 후속 학습의 split은 예시·문체 reference 생성 전에 고정하고 reference는 train에서만 구성한다. 이미 분석해 기준 설계에 사용한 원문을 미관측 최종 test라고 부르지 않는다. 일반화는 분석에서 제외한 별도 자료 또는 독립적으로 만든 새 집필 과제로 확인한다. 사후 분석에는 이후 전개를 참고할 수 있지만, 학습 입력의 이전 문맥·인물 지식에 미래 결과를 섞지 않는다.

## 4. B1에서 결정할 네 가지 규칙

기간 내 미검토 원역사가 없다는 집필 전제는 핵심 설계에 반영되어 있다. 다음 사항은 앞선 논리 검토에서 남은 설계 결정이며, 이 계획에서 승인된 정책으로 간주하지 않는다.

1. **계획 승인 조건:** 부족·충돌·미확인 중 무엇을 창작 가정으로 수용하고 무엇을 해결 전 보류할지 정한다. 공개 사실이나 명시된 제약과의 충돌을 단순 승인으로 지우지 않는다.
2. **부분 잠금과 선행 조건:** 잠긴 사건의 필수 선행 사건·자원·가정을 함께 보호하고, 변경 시 어떤 승인·패킷·초안이 재검토 대상인지 정한다.
3. **비서술 사건:** 직접 묘사하지 않은 배경 사건과 사건의 불발을 어떤 근거로 확정하는지, 발생·독자 공개·인물 인지를 어떻게 나눌지 정한다.
4. **게시 중 계획 변경:** 외부 게시 후 내부 반영 전 계획이 달라진 경우의 차단·복구를 정한다. 단순 버전 재검사와 동일 ID 재시도만으로 해결된다고 가정하지 않는다.

각 규칙은 짧은 정상/실패 예제와 기대 결과로 확정한다. 규칙을 결정한 다음 해당 구현과 의미 검사를 함께 추가한다.

## 5. 바로 시작할 첫 작업

**선행 원문 분석·검토는 완료했고, 지금의 R 작업은 작가 간 비교와 사용자가 선택할 집필 기준을 정리하는 것**이다. [이번 작업 현황](../research/writing-spec-v0-1/README.md)에서 근거·반례가 연결된 비교표, 미승인 집필 기준 초안, 기존 원문 정답의 입력 역구성 계약과 개발용 파일럿을 교차 검토한다. 다음에는 사용자가 취향과 사용할 기존 원문·구간을 선택한다. 학습 예시·문체 reference 생성 전 split을 고정하고 정답 대조·누수 검수를 거쳐 A1의 작은 학습을 구체화한다. B1의 합성 계약 검토는 병행할 수 있다. 실제 학습이나 역사 설계·잠금 구현이 완료되었다는 뜻은 아니다.

아래는 다음 실행용 명령이며 이 문서 작성 중 설치를 수행했다는 뜻이 아니다. 기존 venv가 있으면 상태를 확인해 재사용하고 덮어쓰지 않는다. 모노레포 루트 venv는 사용하지 않는다.

```sh
cd /Users/ahnjunwoo/dev/novel/toy-tune
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/toy-tune doctor --runtime configs/runtimes/local-cpu.toml
TOY_PLAN_WORKSPACE=$(mktemp -d)
.venv/bin/toy-tune prepare --runtime configs/runtimes/local-cpu.toml --workspace "$TOY_PLAN_WORKSPACE" --source tests/fixtures/synthetic-source.json --split configs/datasets/synthetic.toml
```

`prepare`가 반환한 `artifact_id`로 [README의 verify-dataset 절차](../../toy-tune/README.md)를 실행한다. 임시 디렉터리는 검사용이고 실제 원문·채택 모델의 보존 위치는 별도로 정한다.

R 이후 현재 `TrainingEngine`/`GenerationEngine`과 파일 저장소가 tokenizer·checkpoint 디렉터리·생성 결과를 수용하는지 확인하고, 첫 학습에 필요한 최소 변경을 정한다. 단계별 필요한 입력은 다음과 같다.

| 필요한 시점 | 사용자 입력·환경 확인 |
|---|---|
| R 소설 분석 | 작가 4명과 공유 Drive 위치, 구조 지도·대표 장면 분석 범위는 확정. 작품별 실제 수록 범위는 담당 에이전트가 확인 |
| A1 실제 학습 | 사용할 원문과 구간, 학습용 Gemma checkpoint/revision, H200 접속·이미지·스토리지 |
| B2 실제 자료 구축 | 작품 기간·지역·주제, 사용할 영어 자료 묶음, DB·자료 저장 위치 |
| B3 실제 역사 기획 | 결말 앵커·목표일·금지 전개, SOTA 역할 모델·전송 범위·호출 예산 |
| C2 실제 공개 | 작품·원고·전표 승인, 로컬 확정 또는 외부 게시 방식 |

입력이 없는 동안에는 합성 데이터와 로컬 계약 검증을 진행할 수 있다. 실제 작품·원문·결말을 임의로 정하지 않는다.

## 6. 작업 기록 방법

각 단계는 대상, 입력, 산출물, 완료 조건을 범위로 삼는다. 완료 후 실행 명령·실측 결과·실패·산출물 위치를 `docs/reports/`에 기록하고 이 계획의 상태를 갱신한다. 단순 인터페이스 정의와 실제 실행 성공을 구별한다. 상세 절차는 기존 하위 계획을 재사용하되 해당 작업과 충돌하는 저장소·단계 순서를 먼저 수정한다.

후속 확장은 큰 자료 집합, 문체 검색 자동화, 장문 집필, MLX 변환·64GB 맥북 실측, 아카이브 복원 순으로 실제 필요에 맞춰 진행한다. 기존 도구 전체 이식이나 UI 구축은 첫 장면의 완료 조건에 포함하지 않는다.

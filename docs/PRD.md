# 대체역사 소설 집필 시스템 — 제품 요구(PRD)

상태: 현재 합의한 제품 목표와 첫 완성 범위의 기준이며, 남은 결정은 아래에 명시한다. 기술 목표·실행 완료·작가의 작품 승인 상태를 혼동하지 않는다. 근거는 [핵심 시스템 설계](systems/README.md)와 [사용자 결정](harness/session-decisions.md)이다.

## 목적과 사용자

이 제품은 **작가가 정한 결말과 작은 역사 앵커들을, 재미있고 역사 전문가도 납득할 만한 대체역사 소설로 이어 쓰는 작업**을 돕는다. 주 사용자는 앵커·취향·역사표·최종 원고를 선택하고 승인하는 작가다. AI는 근거와 대안을 제시하고 반복 설계·집필을 수행하지만 작가의 선택을 대신하지 않는다. 첫 완성 범위는 **한 작품을 연속 집필할 수 있는 전체 흐름**이다. 여러 작품의 동시 운영은 이후 확장 대상이며 첫 완성의 필수 조건은 아니다. [핵심 설계 §1–3](systems/README.md#1-만드는-것)

## 핵심 사용 흐름

1. 작가가 작품 기간·결말·목표일·금지 전개와 여러 작은 앵커를 정한다. 집필에 사용할 기간과 필요한 배경의 원역사를 검토 완료 상태로 고정한다. [핵심 설계 §2·4](systems/README.md#2-역사-설계의-규칙)
2. SOTA가 정본 역사와 작품 개변 역사를 비교하며 앵커 사이의 조건과 사건을 역산하고, 필요한 중간 사건을 Backfilling한다. 시간·자원·인물 동기·후속 영향을 정방향 검토해 충족·부족·충돌·미확인을 설명한다. 작가는 개연성과 재미를 보고 후보를 선택한다. [앵커 이음새 §목표·흐름](systems/20260924-history-ontology-and-anchor-bridges.md#작은-구간-이음새의-작업-단위)
3. 작가가 승인한 중간 사건까지 역사표를 잠근다. Gemma는 잠긴 역사표와 장면 명세를 받아 학습된 문체로 본문을 쓰고, 검수 결과에 따라 고친다. 정확한 원고·전표 묶음만 작가의 선택을 거쳐 작품의 단일 정사에 반영한다. [핵심 설계 §3·5–6](systems/README.md#3-역사표가-먼저-본문은-그-실현)

## 제품 요구

- 역사·과학·인물의 **공용 원역사 정본**과 작품별 **개변 후보·승인 역사표·공개 정사**를 구별하고 출처·판·불확실성을 추적한다. 원역사 전체를 작품마다 복제하거나 작품 설정으로 공용 원역사를 바꾸지 않는다. [핵심 설계 §4](systems/README.md#4-원역사와-작품-역사의-경계)
- 작가가 잠근 앵커·계획 사건·금지 조건은 집필 패킷과 검수의 제약이다. 계획 변경은 영향 검토와 재승인을 거치며 공개된 정사를 새 계획으로 덮어쓰지 않는다. [핵심 설계 §3](systems/README.md#3-역사표가-먼저-본문은-그-실현)
- 집필 검색은 작품 기간·검토 완료 범위·관련 배경부터 시작하고 장면의 시점·지역·주제·인물 인지로 좁힌다. 기획자가 아는 미래를 인물 지식으로 전달하지 않는다. [핵심 설계 §4·검색 범위](systems/README.md#작품-기간과-장면별-검색-범위)
- 재미와 역사적 납득 가능성을 함께 평가하되, 유일한 필연 경로·인과 확률 점수·모든 미시 변수의 완전 재현을 요구하지 않는다. 해결되지 않은 간극과 창작 가정을 작가에게 드러낸다. [핵심 설계 §1–2](systems/README.md#1-만드는-것)
- 리첼렌·간다왼쪽·명원·마늘맛스낵의 보유작 분석을 서사·장면·문체 기준의 출발점으로 사용한다. 기존 원문은 학습 정답이고 SOTA가 이전 문맥·가상 역사표·장면 명세를 역구성한다. 작가별 취향과 학습 투입은 별도로 선택·검토한다. [핵심 설계 §5](systems/README.md#5-모델과-데이터의-역할), [회차 분석 현황](plans/20260924-first-50-analysis-and-ingestion-plan.md)

## 첫 완성 수락 기준

- 같은 작품에서 앵커·조건 입력 → 경로 제안과 불확실성 설명 → 작가 승인·잠금 → Gemma 본문과 검수 → 확정 원고의 상태를 다음 회차 계획에 반영하는 흐름을 반복할 수 있다.
- 잠긴 조건과 기존 작품 정사의 모순을 검수하고, 수정·재승인과 결과 원고의 연결을 추적할 수 있다.
- 작업을 중단해도 동일한 승인 계획판과 확정 원고 상태를 읽어 다음 회차부터 재개할 수 있다. [핵심 설계 §3·6](systems/README.md#3-역사표가-먼저-본문은-그-실현)

## 첫 완성에서 제외하거나 미결인 것

- 역사 전체를 선행 구축한 뒤에야 작은 학습·합성 검사를 시작한다는 전제, 여러 작품의 동시 운영, 판매량이나 흥행의 자동 예측은 첫 완성 요구가 아니다. 이는 향후 확장을 금지한다는 뜻이 아니다. [현행 실행계획 §2–3](plans/20260918-current-system-execution-plan-v0-1.md#3-실행-순서와-완료-조건)
- **원고 전달 경계 미결:** 첫 완성의 끝이 로컬 저장·내보내기인지, 연재 플랫폼 게시까지인지 사용자의 선택을 기다린다. 어느 쪽이든 외부 게시와 작품 정사 반영은 별개의 승인·복구 경계다. [핵심 설계 §6](systems/README.md#6-교체-가능한-기술-변하지-않는-계약)
- 실제 첫 작품·기간·앵커, 채택할 취향과 학습 구간, 이음새의 세부 입력·평가 규칙은 아직 확정하지 않았다. 임의로 정하지 않는다. [실행계획 §4–5](plans/20260918-current-system-execution-plan-v0-1.md#4-b1에서-결정할-네-가지-규칙), [앵커 이음새 §남은 질문](systems/20260924-history-ontology-and-anchor-bridges.md#남은-설계-질문과-현재-상태)

## 현재 상태

원문 7편의 재사용 코퍼스 적재와 대표 표본 분석·작가별 검토는 완료됐다. 1–50화의 화별 의미 분석 350개, 실제 Gemma 학습, 중앙 운영 DB, 역사 설계·잠금·공개 흐름은 아직 완료되지 않았다. 이 문서는 제품 요구이며 구현 완료 판정은 [원문 검토](research/chapter-ingestion/review.md), [회차 분석 계획](plans/20260924-first-50-analysis-and-ingestion-plan.md), [현행 실행계획](plans/20260918-current-system-execution-plan-v0-1.md)의 실측 상태를 따른다.

# 세션 하네스: 결정과 진행 상태

기준일: 2026-09-28. 이 문서는 대화에서 지속할 사용자 결정과 확인된 실행 상태를 짧게 보존한다. 새 대화는 이를 최신 사용자 지시 및 [핵심 시스템 설계](../systems/README.md)와 함께 읽는다. 상충 시 우선순위는 [위키 진입점](../wiki/index.md)의 판단 순서를 따른다. 이 문서는 원문, 승인 원장, 실행 계획을 대체하지 않는다.

## 사용자가 정한 작업 계약

- **역할 분담:** 루트는 Astra(`gpt-6-astra`) 오케스트레이션을 맡고, 실무는 Sol(`gpt-6-sol`)과 Luna(`gpt-6-luna`)가 나눠 맡는다. 모델 이름은 사용자가 지정한 실행 역할이다. 실제 API 가능 여부와 설정 형식은 별도 검증 대상이며, 이 문서에서 지원 상태를 확정하지 않는다.
- **현재 실무·검토 모델:** Sol 6.0(`gpt-6-sol`). Codex CLI 등 특정 실행 수단을 필수 조건으로 고정하지 않는다. 작업별 실행 기록에는 사용 모델과 실제 실행 수단을 별도로 남기고, 해당 경로에서 지정 모델이 동작하는지 확인한다.
- **이번 원문 역구성 데이터셋:** 《폭군 고종대왕 일대기》는 Gemma 문체 학습용, 마늘맛스낵의 《고려, 신대륙에 떨어지다》·《폴란드 여왕 키우기》는 SOTA 기획용으로 분리한다. 사용자가 확정한 선정 범위는 각 작품의 전체 원문이다. 이미 동결한 초반 1–50 구간은 개발 자료로 보존하고 중·후반 선정분을 추가한다. 전체 범위 선정은 모든 회차·장면의 전수 분석이나 실제 모델 학습 완료를 뜻하지 않는다. 세부 실행 상태는 [데이터 작업 기록](../../data/training/reverse-20260925/private/orchestration/root-state.json)에 남긴다.
- **선호 작가 연구:** 대상은 리첼렌·간다왼쪽·명원·마늘맛스낵. 기존 표본 작업의 역할은 작가 한 명을 검토하는 Sol과 작품 한 편을 분석하는 Luna로 나눈다. 처음 승인한 범위는 구조 지도와 초·중·후반 대표 장면 분석이었다. 사용자는 이후 각 작품의 1화부터 50화까지 각 화 전체를 따로 분석하도록 범위를 확장했다. 대표 표본은 회차별 분석을 대신하지 않는다.
- **역사 설계와 집필:** 사용자가 정한 결말 앵커에서 역설계한다. 집필 전에 사용할 기간(예: 1453–1600)과 필요한 배경의 원역사 검토를 완료해야 한다. 검색 범위는 그 기간과 필요한 배경으로 한정한다. 작가가 승인한 역사표는 잠근 뒤 Gemma가 장면으로 실현한다.
- **재미 우선의 품질 기준:** 대체역사 소설이므로 재미가 먼저다. 역사 전문가도 납득할 만한 개연성이면 충분하며 실제 역사의 모든 미시 변수를 완전히 재현하거나 필연성을 증명하는 것이 목표는 아니다. 납득 가능한 후보들 가운데 작가가 더 재미있는 경로를 선택한다. 이 원칙은 지정 전표·고정 앵커·시간·승인 정사·인물 인지의 핵심 모순을 허용하지 않으며 전문가 전수 승인 절차나 성능 검증 완료를 뜻하지 않는다. [핵심 설계](../systems/README.md#1-만드는-것), [상세 문답 정리](../systems/20260924-history-ontology-and-anchor-bridges.md)
- **역할과 역설계:** 역사 경로·플랜의 필요조건 역산, 중간 사건 Backfilling, 정방향 검토는 SOTA가 맡는다. Gemma는 승인·잠긴 역사표와 장면 명세를 학습된 문체로 본문에 구현한다. 기존 소설 원문을 정답으로 삼는 학습 입력 역구성은 역사 경로 생성과 별개의 작업이다. [핵심 설계 §2·5](../systems/README.md#2-역사-설계의-규칙)
- **정본 역사와 앵커 이음새:** 사용자는 시계열이 명확한 전 세계 역사·과학·인물 등의 정본 온톨로지와 작품 개변 역사를 상호 분석하려 한다. 지정·채택한 역사전표와 그 안의 조건·효과·인과관계는 계산 입력 사실로 두되, 위키 원문 전체의 무오류나 미기재 관계 확정으로 확대하지 않는다. 큰 전쟁과 선전포고·전투·점령·조약 같은 작은 사건을 함께 두며, 여러 작은 앵커 사이의 역사적 핍진성 있는 이음새를 생성·검토한다. 실제 역사 사건을 앵커로 삼아 복원 경로와 실제 전개를 대조하는 평가가 목표다. 시간은 미래 사건의 과거 영향 금지와 개변 전 사실 보존에 쓰며, 시간순만으로 인과를 확정하지 않는다. [문답 설계 정리](../systems/20260924-history-ontology-and-anchor-bridges.md)
- **문답과 실행의 경계:** 초기 역사 온톨로지 문답·문서화 단계 뒤 사용자가 2026-09-27 **제품 구현 시작**과 I1 전환을 승인했다. 이어 실제 한 회차 DB 분석, I2 학습 릴리스·`toy-tune` 연결 및 소규모 H200 시험에 “그래 일단 해보자”라고 답했고 실행 장소를 **kt cloud AI Nexus**로 지정했다. 단계별 실제 완료는 [현재 체크포인트](current-checkpoint.md)에서 확인한다. 이 승인이 위키 덤프 전량 처리, 작품 역사표 잠금·정사 발행을 완료로 만들거나 작가 선택을 대체하지 않는다.
- **학습 입력:** 학습 정답은 기존 소설 원문이다. SOTA 입력은 그 정답 장면을 만들었을 이전 문맥·가상 역사표·장면 명세를 역구성한다. 역구성은 원저자의 실제 기획 의도나 작품의 승인 캐논이 아니다.
- **자료 재사용:** 확인된 소설 원본 파일은 `docs/references/`에 보존하고, 분석 입력은 코퍼스 DB의 고정 원문판·분할판·승인 구간에서 조회한다. 분석 결과·검토 상태는 DB에 저장하며 HTML·학습 JSONL은 DB에서 생성하는 파생물이다. 글공장 문서 위키와 작품별 LLM Wiki를 구별한다.
- **다국어 역사 자료 저장:** 사용자는 H200 컴퓨트 세션에 연결된 2TB 저장 공간을 당분간 주저장으로 쓰고 A40에 주기적으로 옮겨 **원본 삭제 없는 백업**을 두기로 했다. 원문 텍스트·구간과 언어/revision, H/K/B/F 후보·근거, 벡터·모델판, 처리 상태는 영속 DB의 대상이며 압축 덤프는 파일 보관이 가능하다. 작은 시험용 PostgreSQL 16·pgvector는 H200 연결 Storage에 실제 설치·실행됐고 동일 Storage의 새 CPU 세션 재연결도 시험했다. 이는 현실 역사 릴리스 운영 채택이나 NFS 서버 측 내구성·A40 백업 완료가 아니다. 실제 판·범위는 [현재 체크포인트](current-checkpoint.md)에서 확인한다. [보수 플랜](../plans/20260927-wikipedia-multilingual-remediation-plan.md)
- **H200 자료 전송:** 사용자는 이번 다섯 대상 공개 위키 255개 본문·매핑 CSV·실행 코드의 고정 묶음(1,513,326 bytes, SHA `95a3c762fb3bd12e01811f984589860b2f194bc8612d514ed1357906e1e273fe`)을 기존 AI Nexus H200 세션의 `/home/work/novel-toy-tune/ontology-multilingual-expanded/`로 전송하도록 명시 승인했다. 이후 H200 전송은 **`.env` 계열 환경파일을 제외하고 승인**한다고 밝혔다. 후속 전송 묶음에서는 `.env`, `.env.*`, `*.env` 파일을 명시적으로 제외한다. 키와 소설 자료는 이번 공개 위키 묶음에 포함되지 않았으며 A40·다른 목적지·외부 게시는 이 문구의 승인 범위가 아니다.
- **고정 100단위 추론 구성과 본측정:** 사용자는 BF16 한 엔진과 FP8 두·세 엔진의 H200 세팅·기존 위키 추출 중지에 이어 **속도·품질 본측정**을 승인했다. [setup 기록](../research/20260928-h200-ontology-benchmark-setup.md)은 기존 DB의 원문·raw·후보를 보존하고 고정 100단위의 byte/hash 및 BF16/FP8 토큰 동치를 확인했다. B3는 고정 문맥의 BF16 KV 부족으로 첫 엔진부터 기동 불가였다. [A100+B2 100 실제 본측정](../research/20260928-h200-ontology-benchmark-results.md)에서는 두 구성이 같은 100구간을 각 1회 처리해 원시응답 200개를 별도 SQLite에 보존했다. 이번 고정 표본에서 B2는 A보다 느렸고 두 구성 모두 원문 정합성 중대 오류가 남았다. 기계 검증·두 Sol의 분할 의미 검토를 기록했지만 이는 현실 역사 릴리스나 H/K/B 후보 자동 수락이 아니다. 기존 PostgreSQL 수는 setup 종료 때와 같으며 B3 강제 재시도·기존 추출 자동 재개는 하지 않는다.
- **운영 의도:** 루트의 토큰 부담을 낮추고 작업을 분담한다.
- **문서 캐논 선별:** 캐논 계통을 불필요하게 늘리지 않는다. 문서의 연수나 종류만으로 채택하지 않고, 후속 판단에 반복 적용할 독립 기준이 필요한지와 탐색·동기화·모순 관리 비용을 함께 본다. 기존 기준의 개정·결정 통합과 원문 링크를 먼저 고려하되 서로 다른 책임을 한 문서에 무리하게 합치지 않는다. 실행 계획·단발 감사 등은 보통 비캐논 근거로 보존하고, 필요할 때만 별도 계통을 채택한다. [선별 기준](document-lifecycle.md#canon-선별-기준)
- **문서 메타데이터 표시:** `created_at`은 빈 파일이 아닌 최초 내용 저장판을 기준으로 기록한다. 관리 Markdown의 YAML에도 불리언 `canon`을 표시하되 선택 정본은 문서 SQLite이며, 수동 YAML 수정으로 채택하지 않는다. 기존 관리판의 날짜는 보존된 최초 내용판의 유효한 `updated_at`으로만 근거를 기록해 보완하고 미관리 legacy의 과거 생성 시각을 추정하지 않는다. [생애주기 설계](document-lifecycle.md#정본과-식별자)

## 확인된 실행과 미완료 작업

- **문서 생애주기 하네스 — 로컬 초기 구현:** 사용자가 설계의 구현을 요청해 [전용 CLI](../../tools/document_harness/README.md)와 별도 SQLite를 만들었다. `docs/`·`plan/` Markdown 99개를 원본 수정 없이 legacy 판으로 적재하고 모두 `canon=false`로 유지했으며 파일별 SHA-256은 [초기 manifest](../../data/document_harness/initial-import-manifest.json)에 있다. 이어 하네스 문서 4개와 CLI 안내의 관리판만 명시 채택했다. 이 값은 문서 탐색에서 적용할 판이며 사용자 승인 역사표·작품 캐논이 아니다. 관리 문서의 생성·개정·수입과 명시적 채택/유지/철회는 CLI가 다룬다. 전체 과거 개정 이력이나 기존 문서의 현행 선별을 완료했다는 뜻이 아니다.
- **초기 작가 표본 분석 — 완료(제한된 범위):** 7편의 구조 지도·대표 장면 분석과 작가별 Sol 검토 4건을 마쳤다. 이는 7편 전편의 의미 분석이나 전수 정독이 아니다. [작가 연구 현황](../research/author-study/README.md)
- **원문 적재 — 완료·독립 검토 수락:** 7편, 원문 61,533,769 bytes, 현재 분할판 3,292구간을 분석용 SQLite에 보존했다. 첫 50화 번호 대응은 249/350 확정, 고종·고려 100건 미확정, 콧수염 41편 중복 1건 충돌이다. 미확정 대응도 원문은 보존되어 있다. [코퍼스 현황](../research/chapter-ingestion/README.md), [독립 검토](../research/chapter-ingestion/review.md)
- **제품 첫 분석 절편 — 구현·독립 수락:** 원문판·분할판·확정 회차 또는 승인 구간을 고정한 DB 입력, 제출 JSON 원바이트 저장·재조회, 다른 검토자 판정, DB 상태 재개를 [제품 CLI](../../src/novel_factory/README.md)에 연결했다. Sol 코드 검토와 Luna의 실제 코퍼스 **사본** 위치·hash 대조를 받았다. 첫 전환에서는 [백업·검증 기록](../../data/analysis/product-i0-i1-verification.json)에 따라 원문·분할판을 바꾸지 않고 빈 분석 테이블을 추가했다. 합성 결과는 사본에만 있다.
- **기존 역구성 상태·뷰어·반출 — DB 전환 완료:** 후속 사용자 승인으로 수락 272건·보류 후보 21건과 선정·시도·검토 수정 이력·원자료를 운영 코퍼스 DB의 고정 판 `reverse-20260925-i1`로 이관했다. 독립 Sol 검토를 수락했고 백업·복원·원문 불변 및 학습 JSONL 9개 바이트 동치를 확인했다. [검증 기록](../../data/analysis/product-i1-migration-verification.json), [DB 기반 뷰어·반출 사용법](../../tools/reverse_dataset/README.md). 기존 파일 쓰기 명령은 종료했으며 뷰어와 학습 파일은 DB 파생물이다. 과거 보류·검토 이력은 `legacy-status`로 찾고 새 분석은 별도 DB 작업으로 진행한다. 이관판의 보류를 새 작업으로 자동 승계하지 않는다. 이관 완료 시점의 신규 분석 네 테이블은 0건이었으며, 이관 자체는 350화 분석·학습 투입·작품 정사 승인과 구분한다.
- **공식 1화 실제 분석 — 독립 수락:** 후속 승인에 따라 Poland 공식 1화를 고정 DB 입력으로 분석했다. Luna의 v1을 다른 Sol이 보류하고 보완한 v2를 수락했으며 두 제출판과 두 검토를 운영 DB에 보존했다. 정확한 판본·SHA와 `resume=complete`는 [현재 체크포인트](current-checkpoint.md)에 있다. 완료 범위는 이 1화 분석 검수이며 350화 전수 분석이나 학습 채택으로 확대하지 않는다.
- **I2 학습 릴리스 — 운영 발행·소규모 GPU 연결 완료:** 독립 Sol 수락과 Luna 기계 대조 후 운영 DB에 문체용 90건과 기획용 182건을 역할별 불변 릴리스로 발행했다. 기존 개발 분할을 보존하며 문체용 학습 분할은 56건이다. 고정 패킷 90건의 실제 토큰화·정답 경계를 확인하고 그중 train 두 건으로 H200에서 2스텝 LoRA 학습·어댑터 저장·새 프로세스 재로딩을 완료했다. 다른 Sol이 실제 결과와 반입 코드를 수락해 운영 DB에 `writing_eligible=false`인 모델 후보로 등록했다. CPU 데모는 별도 사본에만 있다. 실제 가중치 변경과 실행·후보 식별자는 [검증 기록](../../data/analysis/product-i2-training-verification.json)에서 확인하며, 이 시험을 문체 품질 평가로 간주하지 않는다.
- **I2 원격 전송 범위 — 명시 승인:** 사용자는 소설 원문 발췌 정답·학습 입력·출처 정보를 포함한 고정 문체 패킷 90건을 현재 로그인한 kt cloud AI Nexus의 전용 세션 `novel-toy-i2-20260927`, 영구 폴더 `/home/work/novel-toy-tune`로 전송하는 데 명시 동의했다. 이어 독립 검토를 마친 `toy-tune` 코드·설정·테스트·사용법 묶음(SHA `d4d8c1ba2c2ef395ce7d62c889bb931ce5ce13641214600ecc13041dd2b65038`)과 실행 요청 JSON의 같은 목적지 전송도 명시 승인했다. 소규모 시험의 optimizer 입력은 그중 `train` 분할의 일부다. 이 문장은 당시 I2 승인 범위이며, 후속 H200 전송에는 위의 최신 사용자 결정과 `.env` 계열 제외 조건을 따른다. 다른 목적지·공개 게시 권한으로 확대하지 않는다.
- **확장된 1–50화 분석 — 1화 시범 완료, 전수 미완료:** 7편 × 50화 = 350개의 독립 분석 카드 목표 중 Poland 공식 1화의 DB 분석·검토를 완료했다. 각 작품 1→50 순서로 화별 전체 본문을 읽고 카드를 만들며 회차 경계가 불명확하면 해당 목표를 보류한다. 기존 대표 장면 표본 분석은 화별 전수 작업을 대신하지 않는다. [통합 계획](../plans/20260924-first-50-analysis-and-ingestion-plan.md)
- **본 학습과 역사·집필 운영 — 미완료:** Gemma 소규모 연결 시험 이후의 본 학습·문체 품질 평가, 현실 역사 운영 DB·벡터 질의 구축, 역사 설계·잠금·공개 경로 구현은 완료 상태가 아니다. 목표와 구현 상태는 [시스템 설계](../systems/README.md) 및 [현재 체크포인트](current-checkpoint.md)를 확인한다.
- **역사 온톨로지 문답 정리 — 통합판 독립 검토 수락:** [정리 문서](../systems/20260924-history-ontology-and-anchor-bridges.md)에 최신 재미 우선 기준, 역설계·Backfilling, 온톨로지 항목 도출법을 통합했다. 다른 Sol이 수정본을 검토·수락했다. 이것은 온톨로지 적재·인과 계산기 구현·실제 역사 복원 평가 완료가 아니다.
- **위키 범위:** 2026-09-24에 글공장 문서 위키의 1차 종합을 만들었다. 83개 원자료 목록을 전문 독해했다는 뜻은 아니다. 작품별 LLM Wiki는 별도 자료층이며, 위키의 존재만으로 원문 분석·승인·캐논 반영을 주장하지 않는다. [위키 진입점](../wiki/index.md), [위키 변경 로그](../wiki/log.md)

## 실행 시 적용할 작업 원칙

다음 항목은 위의 사용자 결정과 구분되는 **하네스 적용안**이다. 대화에서 관찰된 작업상 교훈을 실행 기록으로 바꾸되, 새 승인 절차를 만들지는 않는다.

- 작업을 맡길 때 입력 범위, 기대 산출물, 담당자와 파일 소유권을 함께 적는다. 담당자는 자신에게 배정된 파일만 편집한다.
- SQLite 적재는 한 writer가 직렬 처리한다. 분석·검토 산출물은 원문 revision, hash, 좌표, 근거와 검토 상태에 연결한다.
- 긴 분석은 재개 가능한 묶음과 체크포인트를 둔다. 실행 슬롯 한도 안에서 분담하고, 독립 문맥을 전제로 한다.
- 보고할 때 목표·계획·실행 확인·검토 수락·사용자 승인·미결정을 섞지 않는다. 완료 수치는 연결된 검토 기록으로 확인하며, 일부 표본을 전수 완료로 부풀리지 않는다.

이 원칙은 작업을 추적 가능하고 이어서 할 수 있게 하는 방법이다. 문서 수정만으로 사용자 승인, 역사표 잠금, 정사 반영, 학습 투입 상태가 바뀌지 않는다. 근거 확인은 [위키 작업 지침](../wiki/AGENTS.md)과 [위키 규칙](../wiki/rules.md)을 따른다.

# 독립 Sol 사전 검토: YAGO 4.6, 1899년까지의 기초 현실 SoT

상태: **설계 조건 전달 완료, 구현·원격 실행·릴리스 수락 대기**. 이 기록은 기존 파일럿 코드와 승인된 작업 범위의 사전 검토다. 세계사 전량 처리, 역사적 진실, 작품 사용 적격을 수락한 기록이 아니다. 검토자는 코드·DB·원본에 쓰지 않았다.

## 고정 입력과 범위

- [작업 카드](../task-card.json) SHA-256 `9f3f3e2b1167e20b30c2483a34e2c8b886c80249905b02fa8407dce036229741`: 사용자 확인에 따라 **1899년 포함 그 이전 전체**, 임의의 하한 없음. 원천은 H200 Storage에 검증·보존된 YAGO 4.6 원본이며 Wikidata 진행 중 다운로드는 이번 입력이 아니다.
- [방법론](../../../../docs/methods/history-ledger-sot.md) SHA-256 `2f8eaa88d3647bd4835d383dca8000907d34261053b0a56c0f00a2f124bb6847`, [원본 manifest](../../yago-storage-20260928/manifest-final.json) SHA-256 `da0d761331e3ccb070bfebbc5ecf4ad5db4165eac0ef5bc619444d95f78a70bb`. 이 manifest는 원본 보존 검증이며 새 릴리스의 선택 파일·행 분모나 역사적 품질을 증명하지 않는다.
- [PRD](../../../../docs/prd/wikipedia-history-ontology.md) §2·4는 원 진술 좌표, Meta 연결, 실패·미상 분모, 시간·지식 층 분리와 불변 릴리스를 요구한다. [시스템 설계](../../../../docs/systems/README.md) §1·4는 공용 현실 릴리스와 작품 역사표를 분리한다. 따라서 새 결과의 `source_grounded` 정책 수락은 역사 사실 개별 검증·작품 `ReviewScope`·작가 승인 상태와 구별해야 한다.

## 기존 어댑터의 확장 위험

검토 대상 `src/novel_factory/reality/sot.py` SHA-256 `b79712136558042e815fa4b99eb2920e17d19e356f1ecad5d0286c52fcf40bed`, `src/novel_factory/reality/adapters/sot_postgres.py` SHA-256 `8ccccd4216177ca404c5a12d7e2af585f5c55174d72e05559ff31ffb91686a4e`.

1. 기존 `load_foundation`은 SQLite 전체를 `read_bytes()`로 메모리에 올리고 `(5,152,40,50)`을 강제한다. `make_release`도 전체 claim/source/Meta를 리스트와 사전으로 만들며, PG `publish/read`는 행별 삽입·전 릴리스 snapshot/hash 및 `WHERE id = ANY(ids)`를 사용한다. 원본 해제본 약 78 GB의 세계 범위와 맞지 않는다. 별도 스트리밍 캡처·증분 회계·배치 적재·경계가 있는 readback이 필요하다. 기존 다섯 대상 DB·릴리스는 건드리지 않는다.
2. `DATE_LITERAL`, `YEAR`, `query_interval`은 양수 4자리 연도만 받고 Python `date`의 서기 1~9999 범위에 의존한다. 따라서 기원전·0년·5자리 연도·불완전/비표준 날짜를 조용히 `unknown`으로 바꿔 누락하거나, 날짜 문자열 비교가 잘못될 수 있다. 원 signed lexical value, datatype, 어휘상 정밀도, calendar 미상, 파싱 지원 여부와 사유를 보존하고 숫자 연도 비교를 별도로 검증해야 한다. BCE 표기와 0년의 연대 체계가 미확정이면 판단 보류로 회계한다.
3. r3 `_classify`는 다섯 대상의 `role`, `project_relation`, `trial_entity_id`에 맞춘 한정 규칙이다. `endswith(:Hangul/:Bloomery)` 및 왕·배우자·생몰을 세계사 일반 규칙으로 확장할 근거가 없다. 분류·속성·K 후보·H 사건/상태와 미지원 매핑을 구별하고, 새로운 관계를 무조건 H로 승격하지 않아야 한다.
4. r3의 생몰 `context_range`는 두 앵커가 모두 있고 순서가 맞는 사람에게만 근거 있는 시대 탐색 힌트다. 출생연도가 1899 이하인 주체의 모든 관계를 1899 이전 사실로 받아들이거나, 1900년 이후 사망·수상·관계·K 내용 시점을 생애 문맥으로 밀어 넣으면 누출이다. 출생/사망 장소의 `inferred_event_bound`는 별도 생몰 원 진술과 결합한 후보이며 직접 진술 `valid_time`이 아니다. 한 앵커/무효 앵커/비인물은 미상 또는 별도 보수적 규칙으로 남긴다.
5. r3의 Meta 연결과 release scope는 적은 ID 목록에 맞춰졌다. 전량에서는 RDF* 부모 트리플과 Meta의 출처 파일·행·원 raw를 유지해야 하며, 동일 텍스트 트리플과 여러 출현, orphan/지원불가 Meta를 손실 없이 회계해야 한다. `sot_source_*`의 단순 ID/단일 payload 가정과 release 전체 ID 배열은 새 설계에서 재검토가 필요하다.

## 구현 전에 전달하는 수락 조건

1. **선택 입력과 분모**: 읽는 YAGO 4.6 ZIP/해제 파일, 파일 SHA-256·크기·manifest 항목, 스키마·정책·코드 판을 고정한다. 선택한 파일 각각의 실제 읽은 물리 행/파싱된 진술/Meta/후보·제외·미상·실패·미처리와 reason을 대조한다. 선택하지 않은 파일을 전 세계 YAGO 전량 처리로 주장하지 않는다. 입력 hash 불일치, 분모 틈, source→Meta/claim/decision 고아 연결은 발행 차단 조건이다.
2. **시간 컷오프**: 직접 사건 날짜가 1899 이하면 후보, 1900 이상이면 기초 pre-1900 수락 밖이다. 직접 상태 구간이 경계를 가로지르면 실제 종료값을 그대로 두고 pre-1900과 겹치는 부분만 조회·범위 판정에 쓰며 `1899-12-31`을 원 종료로 위조하지 않는다. 시작·끝을 모두 알 수 없는 경우 보수적으로 별도 `unknown/held` 분모에 둔다. 주체의 출생이 범위 안이라는 이유만으로 날짜가 없는 모든 진술이나 후대 진술을 수락하지 않는다. K 기원/분류와 B 사용·인지 사건은 별도 층이다.
3. **시간 세 층**: 주장 자체의 `valid_time`, 같은 주체 사건 날짜에서 유도한 장소 발생 `inferred_event_bound`, 탐색용 `context_range`는 서로 다른 필드·근거·질의 lane이다. 모든 파생에 basis source/claim ID·규칙판을 남긴다. 파생 범위가 있어도 원 진술의 시간 미상은 그대로다. 컷오프에 걸치는 구간은 원 bound와 선택 범위를 따로 표시한다.
4. **지원불가도 관찰값**: signed/BCE, 0년과 역법, precision, invalid literal, Meta 파서 오류, Meta 없는 상태, 상충·반복 기간, 지원하지 않은 관계/타입은 raw·파일/행 좌표와 사유를 둔다. 파서가 읽지 못한 행을 무관한 0건 성공으로 세지 않는다. 역사 범위의 날짜 미상 분모와 그 취급 규칙을 명시한다.
5. **배치와 보존**: 고정 메모리 상한에 가까운 스트리밍, 재시도 멱등성, 종료 후 정확한 합계를 증명한다. 이번 최소 배치에서는 **완료된 파일 단계**마다 입력 hash·출력·DB 상태를 대조해 재사용하고, 미완료 파일은 안전하게 처음부터 재처리해 정확히 한 번 회계하면 충분하다. 파일 내부 바이트 커서는 필수 조건이 아니다. 원본·Wikidata PID38511·파일럿 PG DB/releases를 보존하고 새 전용 DB를 쓴다. 재개 도중 부분 claim은 최종 수락 분모에 넣지 않는다.
6. **발행 계약**: 사전 검토를 위해 릴리스 ID·manifest·예상 claim/decision/source/Meta 수·표본 원문 대조·쿼리 예시를 준비한다. 독립 검토 및 기계 점검 전에는 최종 불변 릴리스로 발행하지 않는다. 발행 뒤 새 프로세스/읽기 전용 질의로 DB readback·manifest hash·컷오프 반례·기존 파일럿 판 불변·동일 재실행 멱등과 변조 거절을 확인한다. 역사적 진실 검토와 작품 범위 검토는 `not_performed`로 표시한다.

의미 있는 회귀 사례는 `1899`, `1900`, `1890..1910` 상태의 실제 끝 보존, 1800년 출생자와 1901년 사건의 분리, BCE 및 signed/0년/5자리 어휘, 날짜 없는 관계와 누락/역전 생몰 앵커, Meta 부모 일치·orphan·원 raw/행/hash 재조회, K·taxonomy의 시대 사건 누출 방지, 체크포인트 재시작 시 정확히 한 번 회계다.

다음 검토: 엔지니어의 코드·테스트·사전 발행 manifest와 H200 실행 수치를 받아 원본 좌표 표본/쿼리 반례를 독립 확인한다. Luna의 기계 점검과 서로 대조하고, 실제 불변 릴리스의 ID·readback hash·범위 제한을 확인한 뒤에만 최종 수락을 기록한다.

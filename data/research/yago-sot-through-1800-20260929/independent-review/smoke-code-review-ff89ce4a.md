# ff89 수정판: 격리 PostgreSQL 관통 시험 독립 검토

**판정: 합성 fixture의 스캔·재개·readback 경로는 범위 한정 수락. 실제 전량 스캔 결과와 불변 발행은 미수락.** 검토 코드 `tools/yago_history_sot/build.py` SHA-256 `ff89ce4a818d20d0c16f9ea4b7b92d4e9162c48f176cea272adb79560494193a`, smoke driver `tools/yago_history_sot/smoke.py` SHA-256 `6d323ad553cd39c9d63d60c19f9376833236476d7b3a239ec639ab08ec9fb18a`. 로컬에서 의미 시험 `PYTHONPATH=. python3 -m pytest -q tests/yago_history_sot`를 재실행해 8/8 통과했다. 검토자는 H200 PostgreSQL에 직접 접속하지 않았으며, 아래 원격 실행 결과는 보존된 영수증·원 fixture와 코드 계약을 대조한 것이다.

격리 실행 사본 [`smoke-review.tgz`](../run-evidence/smoke/smoke-review.tgz) SHA-256 `1c0ab7a2bb5ace17265702d062e457a6c2a8f1553a6cf17700c5dd959650d5c3`, 그 안의 [`smoke-result.json`](../run-evidence/smoke/smoke-result.json) SHA-256 `e44d7c3adcb8c1054182d94c08e9aa8496d251377307778ca968dd09bae7a5a0`. fixture manifest와 여섯 선택 입력 파일의 SHA를 독립 재계산하여 각 단계 receipt의 source SHA와 모두 일치함을 확인했다. 원 파일 물리행/receipt `all_lines`는 Meta 6/6, facts 13/13, beyond facts 4/4, taxonomy 2/2, labels 4/4, beyond labels 2/2다. facts의 mapped 7 + excluded 3 + unknown 3 = 13, Meta의 mapped 5 + header 1 = 6이다. 이 값은 **합성 소형 fixture**의 분모이며 실제 YAGO 분모가 아니다.

영수증의 readback SHA-256은 `160a0f7a49719478ae8d50d7169ce8e7eb2e9a78cf2738e8a8359a6fcc4c22dc`, 행 수는 claim 7, Meta evidence 4, auxiliary 10, context anchor 1이다. lane은 `H_boundary` 1, `H_event` 3, `H_state` 1, `K_dated` 1, `K_taxonomy_timed` 1. Smoke driver는 1890–1910 Meta 관계의 실제 끝 `1910`, 1900 직접 날짜 제외, K 분리, 유일한 1800/1880 생몰 context와 1901년 사망 인물의 context 제외, labels에 상태·지식 주체 포함, 단계 재진입 중복 방지를 주장하며 assertion으로 검사한다. 보존된 receipt와 fixture는 이 주장과 수치상 일치한다.

코드상 선행 발행 gate 결함도 수정됐다. `publish()`는 acceptance의 코드·manifest SHA뿐 아니라 staging `readback_sha256`, 전체 receipt bundle SHA, 실제 PG 행 수가 정확히 같은지를 확인한다. PG claim/Meta/aux/context 수와 Meta 고아 연결·H 상태 컷오프를 검사한다. `attach_meta` receipt 재개 시 stage seen/orphan과 PG Meta 행 수를 비교하고, context/related Bloom은 hash를 확인한다. `prepublish`는 승인 전에 정확한 비교값을 읽는 별도 단계다. **현재 acceptance JSON은 만들지 않았고 발행을 승인하지 않았다.** Engineer의 발행 거부·불변성 smoke는 이 기록 시점에 아직 수행되지 않았다.

실제 스캔 재개 전 남은 한 가지 체크포인트 결박: ff89의 `completed_receipt('meta')`는 `meta-bloom.bin` 파일의 크기와 stage `meta` 행 수만 비교한다. 같은 크기의 잘못된 Bloom은 Meta lookup을 누락시킬 수 있다. e460 실제 Meta 단계는 [첫 시도 receipt](../run-evidence/first-attempt/meta.receipt.first-run.json)상 720,870,838 byte와 SHA `d6ddcf0803a13fcf69f3b32df2c6f817fc6a807c27bd9cae429287dbc460c020` 검증, `mapped_meta=6,221,745`, header 34, 총 6,221,779행까지 완료했다. 그 뒤 facts 진입 전 `UnboundLocalError`로 종료한 [로그](../run-evidence/first-attempt/scan.log)를 확인했다. 엔지니어에게 현재 Bloom SHA를 고정하고 재개 시 검사할 것을 요청했다. H200 실제 PG Meta stage와 Bloom payload를 이 검토자가 직접 재조회한 것은 아니다.

다음 단계는 실제 선택 파일 전체 scan의 SHA·행 분모·스테이징 PG readback과 Luna 기계 대조, 발행 거부/불변성 시험, reviewer output SHA 결박이다. ff89 코드판의 합성 smoke 수락을 전체 세계사 결과·역사적 진실·작품 `ReviewScope` 수락으로 확대하지 않는다.
